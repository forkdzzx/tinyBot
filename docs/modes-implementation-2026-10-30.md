# 四模式 Skill 与状态切换实现

日期：2026-10-30，Asia/Shanghai。对应 T-28、T-29，部分支撑 T-30。机器人硬件、主动搭话、勿扰和搜索没有在本轮接入。

## 当前结果

Mac 语音页面已接入日常、工作、陪伴、英语练习四种模式。本地状态决定当前模式，页面显示实际状态；模型说自己切换了不算状态变更。四份 Skill 是本地 JSON 文本，启动时校验并加载，编辑后重启生效，不执行代码、不增加工具权限。

| 行为 | 当前实现 |
| --- | --- |
| 手动切换 | “进入工作模式”“陪我看球”“陪我练英语”“不练英语，只是聊天”等明确表达；同一句附带问题仍会交给模型回答 |
| 自动切换 | 明确活动描述如“我正在写代码”可触发；一般话题需连续两轮有足够线索，距上次切换至少两轮。引述、假设、保存记忆请求不触发。采用有限规则，不是任意语义识别 |
| 切换告知 | 页面立即更新；纯切换由设备播报确认，带问题的切换先播报告知，再播放模型回答。插话或点击打断会取消告知及排队回答 |
| 不要切换 | 回滚最近一次自动切换，锁定本次会话的自动切换；仍可手动切换。手动切换后不能再回滚更早的自动切换 |
| 会话边界 | 结束会话保留模式；新会话解除自动切换锁定；重启服务回到日常。勿扰尚未实现，没有暗中解除勿扰的逻辑 |
| 英语练习 | 话题内容及中文求助不自动退出英语模式；明确退出才回日常。遵循当前语言要求，不把大小写和标点作为口语纠错 |
| 未实现 | 英语片段结束总结、词汇与错误归档、学习进度，以及完整十分钟体验验收。“今天练到这里”目前只回日常，不谎称总结已保存 |

## 同步路径与保留的失败

最初要求每轮先调用 `read_mode_context`，并拦住未读规则的回答。[首轮真实合成报告](../runtime/evals/1793374354887-modes.json)显示：第三句未调用工具，最终只播报缺少规则的提示。这条强制路径未通过，已移除，不把工具调用遗漏变成普通聊天的八秒等待。

当前采用：初始提示注入当前 Skill；切换时通过 `conversation.item.create` 同步带明确设备标识的 assistant 上下文；询问当前模式时仍可调用只读工具核对。不伪造用户发言或工具调用编号，不把内部状态文本写成真实说过的助手历史。此上下文事件及角色由[官方协议](https://docs.volcengine.com/docs/doubao-voice/end-to-end-real-time-voice-full-duplex-version?lang=zh)提供；协议支持和发送成功不等于模型完全遵循，仍以实际回答判断效果。此前 `session.update` 的失败结论没有撤销。

[第二轮真实报告](../runtime/evals/1793374847046-modes.json)的 12 句、3 个会话覆盖中文求助、退出英语、自动切换、回滚锁定、手动覆盖、结束保留及服务重启日常；状态检查通过，实际回答可继续聊天。但模型遗漏了自动切换告知，所以改由设备负责告知，先完成提示音频，再释放暂存回答，排队体积有上限，插话会清理。

[告知修正后的定向报告](../runtime/evals/1793375122435-modes.json)覆盖 3 句：自动进入工作并回答线程问题、回滚日常、同一句进入英语并请求话题。两条带问题的回答均先返回切换告知，再返回实际回答，未出现重复告知。这是合成输入与音频字节检查，不是用户外放听感或并发压力验收。

仍有内容缺口：第二轮对 Java 接口的首次回答与后续关于 Java 8 的补充不一致；最后一轮英语开场问句仍偏长。保留到 T-14／T-30 的内容质量回归，不以本地状态正确推导模型内容已经正确。自动规则也可能漏掉自由表达，中文模式命令是本轮重点覆盖范围。

## 校验与运行

- `npm test`：113 项通过，包括 Skill 格式／重载、切换冷却、引述排除、英语求助、回滚锁定和上下文来源检查。
- [本地模式服务回放](../runtime/evals/modes-flow-20261030.json)：切换、状态同步、无工具的普通聊天、跨会话保留／解锁、告知先于回答、按钮／直接插话丢弃告知及旧回答，告知音频失败时继续回答。
- [记忆回归](../runtime/evals/modes-memory-regression-20261030.json)：确认替换、打断后延期及追问、含糊回复保留旧值、保存失败、过时音频清理仍通过。
- 浏览器检查使用静音音轨和模拟连接，覆盖模式显示、锁定提示、按钮重新开始、语音结束、记忆播报与资源释放；不打开真实麦克风，不代替真人体验。[检查结果](../output/playwright/modes-check-result.json)已记录，脚本在 `output/playwright/modes-check.js`。
- 真实云端验证均使用独立 `runtime/evals/*-modes-data/`，合成音频仅在内存，未写入个人 `runtime/data/`。原失败报告保留。服务与合成会产生费用，用量有日志，未据此认定月预算或响应时间达标。

正常服务：`npm run voice`，端口 8766。隔离测试：`npm run voice:memory-test`，端口 8767。本轮新测试目录为 `runtime/evals/memory-manual-ZNdi8t`；此前真人目录与个人记忆保留。

Skill 默认路径为 `prototypes/modes/skills/`，包含 `daily.json`、`work.json`、`companion.json`、`english.json`。只有 `id`、`name`、`instructions` 字段；缺失、错格式、未知字段或超长会以 `SKILL_INVALID_<id>` 阻止启动。可用 `JARVIS_SKILLS_DIR` 指定包含四份文件的目录。当前四个模式标识固定；增加新模式还需改状态控制器，不宣称任意插件可直接安装。
