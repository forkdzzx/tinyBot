# 更正、饮品记忆与打断后回复修复（2026-10-30）

对应 T-24／T-25／T-27。用户补充确认：改绿茶时没有收到询问，也没说确认；乌龙茶播报是主动打断；等待和表达可以接受。原始[真人失败记录](memory-confirmation-feedback-2026-10-30.md)保留。本轮修复程序，不改原测试结果，也不改真实个人记忆。

## 当前行为

- “不，请记住……”可以作为更正后提出保存请求；真正的“不要记住”、引用和条件句仍不能写入。
- 实时写入和后台提炼使用相同的本地分类。已知饮品别名（如 `drink.favorite`、`beverage.preference`）及明确饮品偏好原话统一到 `preference.drink`；原有别名记录参与比较，无需改写旧文件。覆盖范围是有限键名和语句，不是通用语义本体。
- 将普通“喜欢”、明确“最喜欢”、“只喜欢”与不确定表述分开保存。普通喜欢可以与最喜欢并存；替换最喜欢时不会顺带删除其他普通爱好。带更正但没有“最”字的新说法不自动获得“最喜欢”的含义。
- 确认提问仍列出具体旧值与候选原话。肯定更新必须紧接有效问题，且问题已播完；拒绝或延期可以在主动打断后生效，因为它们不替换原事实。
- “先不改／现不改＋当前最喜欢喝什么”的复合句可先延期，再读取旧值回答。若云端分成“先不”和后续问题，也可分别处理；不要求用户一定拆成两句说。
- 对无法确定的回复，例如真实回归中的“心不改”，不会伪造肯定或否定决定。若后半句是支持的饮品偏好查询，则标记本次未完成确认、保留旧值、回答查询；审计为 `unclear`，不冒充用户明确选择了延期。
- 对已覆盖的“我最喜欢喝什么”查询，本地只引用已确认且确有“最喜欢”限定的记录。没有明确记录就说明没有，旧数据互相矛盾则说明待核对，不用普通喜欢或待确认候选填答案。
- 历史新增 `playbackInterruptedAt`，区分中断时刻与之前的播放回执时刻。没有调整音色、语速、基础聊天规则或云端判停参数。

**不能写成“三轮云端测试全部通过”。** 前两轮验证了部分真实保存／提炼／重载路径；第三轮的前置绿茶是本地测试数据，不作为云端保存证据。所有音频输入都是内存中的合成语音，播放完成／打断回执由脚本模拟，不访问真人麦克风，不保存录音。

测试脚本现会发送完整输入并等待后续识别／输出；完整输入在某次云端分句中仍出现较长等待，因此不据此宣布延迟指标通过。用户本轮主观等待感可接受与合成边界问题分别记录。
