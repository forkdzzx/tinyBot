# 正式文字历史与最小跨会话记忆

更新：2026-10-27，Asia/Shanghai（开发及真实服务测试始于 2026-10-26）。对应 [工作清单](work-checklist.md) T-20～T-26。

**最小闭环已接入当前 Mac 页面：用户表达 → 文字历史落盘 → 明确保存或会话后提炼 → 服务重载 → 新会话查询相关记忆。** 这是两条信息的开发验证，尚未达到 PRD 五条记忆、完整冲突确认与日常体验验收。

## 已实现

| 能力 | 当前实现与证据 |
| --- | --- |
| 独立文字历史 | `runtime/data/history/<会话标识>.json` 保存双方文字、时间、来源及轮次；与 `runtime/voice/` 诊断日志分开，不自动轮转删除 |
| 生成与播放区分 | 回答生成完成、浏览器排程／完成、打断分别记录；云端音频生成结束不等于播放完成。没有浏览器确认就不记为完整播完，不能据此证明用户实际听到了声音 |
| 记忆结构 | 会话重点、跨会话资料、个人档案分开；条目保留原话、来源会话／条目、时间、属性键、明确事实／观察和确认状态。这里的事实表示用户明确表达，不等于外部事实已经核实 |
| 明确保存 | 当前明确说“记住”才允许立即写入；精确匹配用户原话，原子写盘成功后才向模型返回保存成功。失败返回明确状态，不虚假确认 |
| 普通内容提炼 | 会话结束后调用已配置的方舟文本模型，异步提炼用户原话；不将助手猜测或回答当成用户自述。会话重点单独标为模型生成摘要，不直接当事实检索 |
| 相关查询 | 通过只读上下文工具返回最多六条相关信息，不将完整旧对话送入新会话。当前采用文字关键词匹配，个人档案略优先，用户当前要求仍优先 |
| 冲突保护 | 相同属性键出现不同值时保留旧事实，新值进入待确认；推测观察及新项目名候选不直接成为已确认长期资料。完整自然确认流程仍未完成 |
| 故障恢复 | 文本和状态采用临时文件、同步写盘、替换；保存任务标记后再调用云端。每个提炼任务最多三次尝试，失败保留状态；重启恢复未完成任务，已完成任务不重复写入 |

普通陈述可能被模型误调用“立即保存”工具。首轮实测出现这种情况：工具拒绝了未经明确请求的立即写入，但模型错误说“保存失败，请再说一遍”。已增加 `deferred` 状态，表明普通内容留待后台处理；定向复测恢复正常接话，随后成功提炼。

用户明确说本句不要记住时，该句不进入长期记忆提炼；完整文字历史仍按既有 PRD 保留。这不是语音删除历史功能。

## 实测

测试资料是虚构测试输入，**全部存放在隔离的 `runtime/evals/` 目录，没有写入用户正式 `runtime/data/`**。没有使用麦克风、真人录音或扬声器。

第一场合成对话先要求记住午后饮品偏好，再普通陈述周末爱好；第一条通过记忆工具即时保存，第二条在会话结束后由真实方舟模型提炼。关闭并重新创建本地服务实例、重新读取文件后，新语音会话正确回答“午后喝乌龙茶、周末烘焙面包”，询问提醒时明确说明没有创建提醒。服务实例重载不是操作系统重启或整机断电测试。

| 证据 | 结果 |
| --- | --- |
| [首轮真实服务报告](../runtime/evals/1793029595857-memory-v1.json) | 跨会话读取成功；发现普通陈述被误说成保存失败，保留失败回答 |
| [修正后真实服务报告](../runtime/evals/1793029777829-memory-v1.json) | 即时保存、普通内容接话、后台提炼、文件重载及新会话两条信息引用成功；未虚称已设置提醒 |

| `npm test` | 59 项通过；新增 17 项覆盖原子保存失败、来源验证、任务恢复／去重、冲突保护、有限重试、播放回执等 |

两轮真实服务测试共生成八条问题音频，建立四场语音会话；后台提炼使用既有方舟配置。第一场提炼完成后才检查跨会话结果；测试结束时第二场的未完成提炼可留在隔离目录中，下次加载该目录时恢复，未被标为已完成。原始报告 `needs_semantic_review` 是脚本不自动判断回答质量的标记，上表是人工审阅结论。

复现入口：`node prototypes/evaluation/run-memory.mjs --live`。会调用真实云服务并产生用量；每次使用新的隔离目录。默认不把历史诊断日志批量导入或上传提炼。

## 本地文件与维护

| 位置 | 内容与维护方式 |
| --- | --- |
| `runtime/data/history/` | 每场完整文字历史；需要人工修正时先停止语音服务，再备份并修改文件 |
| `runtime/data/memory.json` | 个人档案、跨会话记忆、会话摘要、待提炼任务与状态；首次产生记忆或提炼任务后创建 |
| `runtime/voice/memory-worker.jsonl` | 后台提炼完成／失败、任务编号及用量；失败不会删除原始历史 |
| `runtime/volcengine.env`、`runtime/ark.env` | 沿用现有凭证；不发送到浏览器，不写进文字历史或记忆 |

备份时停止服务，复制整个 `runtime/data/`。恢复时也停止服务，完整恢复该目录后启动。直接编辑运行中的文件会与内存状态冲突，不支持热编辑。损坏数据不会自动清空，需保留文件排查。超过三次失败的任务保留 `failed` 与错误码，修复原因后可在停服备份状态下将相应任务改为 `pending`、`attempts: 0`、`notBefore: 0` 再启动。

## 尚未完成

- 关键词检索可能漏掉同义表达；不同属性键的语义冲突尚不能可靠识别，不能把当前保护当成完整冲突检测。
- 自然确认／修正项目名、冲突确认后更新、重复观察晋升、低频压缩与整理仍需实现。待确认条目不会自动升级为事实。
- “记住这个”的模糊指代、更多自然说法及中英混合需继续体验。无法确认来源时不冒险保存。
- 助手回答中的重要知识不会直接沉淀为用户事实；后续可增加带来源和核实状态的知识记忆。
- 四模式 Skill、自动切换／回滚、主动搭话、真实搜索和实体硬件未在本轮实现。
- 真实磁盘耗尽、断电、长期运行、五条信息验收与完整体验仍待检查。

当前人工配合只需一轮[约三分钟的记忆短测](memory-short-test.md)。测试结束后先查看日志，再集中收集体验反馈。
