# 记忆确认与并存偏好（2026-10-30）

本轮对应 T-24／T-25：已接通有明确边界的确认流程，并让受控记忆回复由实际保存结果决定。它们仍为部分完成，尚未经过本轮真人听感验收，也没有实现完整语义冲突检测。当前入口见[工作清单](work-checklist.md)。

## 改了什么

- “喜欢打游戏”“喜欢打篮球”可以并存。普通爱好、饮品、食物等使用有限的集合键；带“最喜欢”“只喜欢”“改成”等限定的值以及项目名称仍需确认。判断同时参考用户完整原句，避免模型摘掉“只／最”后错误保存。
- 真正需要替换时，设备根据旧值和候选原话问一个短问题。确认问题播放完后，下一句说“确认更新”“是的，按新的记”等才会更新；“保留原来的”拒绝候选，“先不改”保留候选及旧事实，不再自动追问同一候选。
- 涉及多条旧值时逐条说清，并明确替换数量。超过三条或内容过长则先保留旧值，不能用笼统的“确认”替换未说明的范围。
- 确认记录绑定会话、提问、紧接的用户回答及旧值快照。未播完、插话、隔了一轮、跨会话、引用他人的“确认”或后台已改变相关记录，都不能触发替换。原始文字和旧事实保留，旧值标为 `superseded`，拒绝值标为 `rejected`，附决策来源。
- 对识别到的明确保存请求、实际记忆写入工具和确认回复，由本地结果决定播报。持久写入完成才说“已经保存”；写入失败或工具未在等待期内执行则说明尚未保存。期间不播放对话模型自行生成的保存承诺。
- 同一事实在后台提炼时带有“请记住”前缀，不再重复建档；被拒绝／替代的同一来源不会在后台重新变成有效记忆。原话本身不改写。
- 查询补充“爱好”“饮品”“喝什么”等有限主题词；这仍是有上限的关键词检索，不是完整语义检索。

## 播报与协议

普通问答继续使用原实时对话连接。上述记忆回复用另一个短时 Seeduplex 连接发送固定文本，通过 `speech_text_buffer.commit` 合成；语音流可取消、有大小与超时限制、不保存录音。文字历史标注 `local_memory`；浏览器实际播放完才回传完成状态，不能用云端生成完代替用户听完。

协议依据：[豆包实时语音模型双向流式协议](https://docs.volcengine.com/docs/doubao-voice/end-to-end-real-time-voice-full-duplex-version?lang=zh)。本机真实服务已返回固定确认问题与保存结果的音频；尚未由用户试听。这个方式增加连接和云端用量，实际额外费用与等待感仍待测量。

固定播报失败时保留准确字幕并回到倾听，不伪报写入失败或强行断开整场聊天。语音插话及页面“打断播报”均取消旧播报。完整播报及主回答结束后，将实际播报文字追加进云端上下文；中途打断时不保证这次同步完成，本地历史与实际记忆仍是依据。
