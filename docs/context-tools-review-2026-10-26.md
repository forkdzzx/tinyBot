## 实际结果

所有问题由合成音频通过真实服务识别，回答同时返回文字和音频字节；没有使用真人麦克风或评判外放听感。资料“松塔／复查日”和“松果节”都是固定虚构案例。

| 检查 | 实际观察 | 结论 |
| --- | --- | --- |
| 新会话注入资料 | 未在问题中透露答案，回答“松塔／周六／日常模式” | 最小案例通过 |
| 新会话不注入资料 | 明确不知道项目代号与复查日，仍为日常模式 | 本组隔离通过；不是长期记忆验收 |
| 同一会话直接更新 | 收到 `session.updated`，会话编号未变；随后仍回答“周六／日常”，没有使用“周二／工作” | **未通过** |
| 显式携带会话编号更新 | 再次收到确认，但仍回答旧日期和旧模式 | **未通过**；不能归因于遗漏编号就结束调查 |
| 新建会话直接加载更新资料 | 正确回答“松塔／周二／工作模式” | 说明新资料本身可被理解；不足以确定直接更新失败的服务端根因 |
| 本地上下文工具 | 同一会话先读原资料，后读版本 2，回答“复查日改成了周二，现在是工作模式” | 更新路径的最小案例通过 |
| 工具返回英语练习状态 | 中文问“现在是什么模式？帮我开个话题”，工具返回英语模式后，回答“What did you do today?” | 模式影响话题的可行性通过；未口头确认模式，不算完整切换体验通过 |
| 模拟查询结果回传 | 服务返回工具调用编号；使用该编号回传后，回答模拟开始时间 14:25，并说明是本地测试资料 | 自定义工具回传通过；没有使用真实搜索 |
| 查询未完成时换题 | 保留待返回查询，输入“换个问题，你叫什么名字”；旧结果在本地失效，回答“我叫 Jarvis”，两秒观察窗口无追加旧答 | 最小换题路径通过；未覆盖所有竞争条件 |

原始 ASR 多次把“复查日”转写成“富察日”，模型仍能结合资料回答。本轮未添加针对这个词的硬编码替换，也没有据此宣称识别质量已解决。

## 路径选择与实现边界

1. **本地保存状态。** 模式、记忆条目及版本的真实值留在本地；模型回答不能当作状态已保存的证明。当前只是内存中的虚构快照，下一步才实现正式存储。
2. **新建会话可注入相关快照。** 只传相关、有限的资料及基础规则，不自动带入整段旧历史。本轮只证明能使用提供的资料，尚无相关性检索器。
3. **会话中需要最新资料时调用只读工具。** 原型 `read_local_context` 返回相关资料、模式和版本。同一个连接在三轮实验中读取不同状态，实际历史仍可查询。尚需验证模型漏调用、连续切换、明确指令优先及低延迟；不把“需要最新资料”简化成每句话都调用工具。
4. **查询结果按调用编号关联。** 模型返回函数调用，设备执行允许的查询后回传。新用户轮次或会话结束使已登记结果失效；固定工具名、参数与结果体积均受限。正式调度仍需处理迟到的函数调用事件、多个工具、超时和断网。
5. **不依赖直接提示更新。** 两个变体均出现“确认成功但仍回答旧资料”。可能涉及服务端更新处理或旧上下文影响，现有证据不足以确定根因。保留失败记录；无需为此立即建设另一套完整语音系统。

官方文档定义了会话更新、工具调用和按调用编号回传结果的事件。本轮依据该版本协议实测；文档列出能力和收到确认都不能替代回答内容检查。[豆包实时语音模型 3.0 接入文档](https://docs.volcengine.com/docs/DoubaoVoice/endtoend-realtime-voice-full-duplex-version?lang=en)
