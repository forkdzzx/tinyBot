# 英语练习收尾与学习记录（2026-11-01）

本轮推进工作清单 **T-30**：在已有英语 Skill 上接入片段收尾、独立学习档案与下一次会话的进度上下文。代码和定向验证已完成，完整英语体验仍为“部分完成”，不是正式验收通过。

## 当前行为

| 触发 | 行为 |
| --- | --- |
| 英语模式说“今天练到这里” | 回到日常模式，整理当前练习，播报简短复习内容；聊天连接继续保留 |
| 说“不练英语，只是聊天” | 日常模式确认；学习整理在后台进行，不主动念复习内容 |
| 点击结束、语音结束、沉默到期或连接关闭 | 保存练习片段并后台整理，不临时插入总结 |
| 整理期间说新问题或点击打断 | 旧总结不再播报，学习记录仍可完成保存 |
| 显式总结整理超过 8 秒 | 说明记录仍在整理，不声称已保存；后续完成只更新状态，不突然补播。8 秒是整理等待预算，不包含识别与语音合成耗时 |
| 进程中断后重启 | 从已保存的片段恢复任务；同一片段不重复归档；失败最多尝试两次 |
| 后续会话 | 注入实际记录数量、最近词汇和表达建议；可通过现有模式上下文工具查询 |

关机中断的恢复仅验证到**本地服务进程**；硬件电源键、勿扰尚未接入，不据此宣称相应实机行为完成。

页面新增“学习记录”一行，显示已整理段数、用户交流轮次、最近接触词和整理状态。超长练习会分片，段数不等于上课次数；中文求助属于练习中的交流轮次。接触过某个词不代表已经掌握，不生成能力等级或发音分数。

## 数据和来源

- 文件：所选数据根目录下 `learning.json`。正常服务为 `runtime/data/learning.json`；8767 隔离页使用启动时显示的 `runtime/evals/memory-manual-*/learning.json`。
- 保存本次英语片段的最终文字转写、已完整播放的助手回复、来源条目 ID、词汇／表达建议及任务状态。不保存录音。
- 不把进入／退出模式、结束口令、已标记排除记忆的用户内容或本地保存提示当作练习。未播完的助手回答不进入整理材料。
- 长文本按大小分片；助手续片携带对应的真实用户原文锚点，避免丢失内容。相同用户 ID 在进度中去重；续片只能获得部分长上下文，仍可能影响整理质量。
- 提炼复用现有方舟配置，不需要新凭证。输出限制为最多三个词汇、三个表达建议；入档前核对引用的 ID、原文及词汇来源，剔除只改大小写／标点的建议。**来源校验不能证明模型的语法判断一定正确。**
- 写入先完成后才播报“已保存”。旧文件损坏时停止启动并保留原文件，不自动清空；初始化失败也不会留下继续提炼的后台任务。
- 学习文件与通用个人记忆分开，不修改已有已确认偏好。当前没有学习记录管理网页，仍通过本地文件与日志维护。

## 本轮发现并处理的问题

1. 首次回环中，Seeduplex 把正确的 “I eat bread for breakfast” 擅自解释为今天吃过的早餐，要求改过去时；整理器又采纳这一判断。原始报告 `runtime/evals/1793544289344-learning.json` 保留。修订英语规则和整理规则，要求独立核对，不能把助手自造的语境当成依据。复验不再保存此错误，但实时回答仍主动提供了 eat/have 同义表达，教学节奏仍需真人判断。
2. 超长已播放助手回答的后续分片没有用户条目，原本会被丢弃；现携带真实用户来源锚点并去重计数。
3. 点击打断时，尚未完成整理的总结原本仍可能迟到播报；现与新一轮讲话一样使旧播报失效，记录保存继续。
4. 学习文件损坏导致启动失败时，原本记忆后台任务仍可能运行；现先完成全部初始化再启动任务，失败时清理。
