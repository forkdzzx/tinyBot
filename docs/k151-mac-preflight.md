# K151 设备协议在 Mac 上的联调记录

2026-11-08。已用两个本机 WebSocket 端点跑通配对凭证校验、同步收音帧、按回答取消、播放回执与断线重连。K151 端由脚本模拟。此次使用合成 PCM，未调用豆包、打开麦克风或写入个人会话。[A2 交付书](../forProject/A2-硬件选型交付书.md) · [设备会话实现](../prototypes/device/session.mjs) · [模拟端与断言](../prototypes/evaluation/check-device-link.mjs)

## 复现

在项目根目录使用已安装的 Node 依赖。本次工位为 arm64 Mac，Node v24.14.1。

```sh
npm run device:preflight
npm test
```

第一条命令在 `127.0.0.1` 的临时端口创建独立设备入口，一次只接受一个模拟终端。凭证在进程内随机生成，通过请求头传入，进程退出即失效。脚本结束时释放端口。正常输出标明 `simulated K151`、`loopback WebSocket`、`cloudCalls: 0` 以及四组通过的场景。现有网页语音入口继续使用自己的地址和来源校验。[设备测试入口](../prototypes/device/bench-server.mjs) · [现有语音入口](../prototypes/voice/server.mjs)

| 现场问题 | 本轮怎样检查 | 结果 |
| --- | --- | --- |
| 能否绕过配对或占用现有连接？ | 分别使用空凭证、错误凭证、携带网页 Origin、错误路径、第二个合法客户端 | 前四项分别收到 401、401、403、404。一个终端在线时，第二个收到 409 |
| 连接时是否已收音？播报时能否继续上传？ | 在主机打开收音前发送一帧，再在主机发送播音帧后回传双轨合成采样，重复发送其中一帧 | 打开前交付给音频处理端的帧数为零。打开后，两路样本逐字节一致，重复帧只交付一次 |
| 上一答被打断，何时能播下一答？ | 主机发取消，终端先回传错误回答编号，再回传正确编号，随后注入旧答音频 | 错误回执期间无法开始下一答，收音仍可继续。正确回执后可以播新答，来自旧答的音频被丢弃；新答可自然播完并回执 |
| 掉线或重开收音会不会混入旧数据？ | 在同一连接关闭再开启收音，然后在播放中断开并重新配对。重放旧收音帧和上一连接的停播回执 | 新收音使用新的采集编号，新连接使用新的会话编号。仅当前帧交付，旧回执无法放行。模拟设备一直不确认时，主机按 `stop_timeout` 关闭链路 |

第二条命令本次通过 **195/195**，含 8 项设备状态机测试。另覆盖错误帧尺寸、采样跳号、等待就绪或播完超时、收音回调失败，以及取消抢在正常播完之前到达的情况。[设备单元用例](../tests/device-session.test.mjs)

## 供固件对接的消息约定

这版工位用 `/device/v1` 上的 JSON 文本和 Base64 PCM，便于检查字段与采样。主机与设备须保持消息有序。真实 Wi-Fi 的封包方式、吞吐和缓冲深度将在样机阶段验证。

| 步骤 | 方向与字段 | 接收方行为 |
| --- | --- | --- |
| 连接就绪 | 设备 → 主机 `ready(version=1)`，主机 → 设备 `ready(version=1, sessionId)` | 主机每条连接生成新的 UUID，之后每条消息都携带它。配对及就绪后收音仍关闭 |
| 开关采集 | 主机 → 设备 `input.open(captureId)`、`input.close(captureId)` | 每次打开产生新编号。未来由启用状态和聊天按键控制打开时机；当前脚本直接调用主机接口模拟开始 |
| 上传双轨 | 设备 → 主机 `mic(captureId, seq, pcm)` | 24 kHz、PCM16 小端，交错排列麦克风和功放参考两路。每 20 ms 含 480 对样本，共 1,920 字节。每次开启收音从序号 0 开始；丢弃旧编号或重复帧。有效采集发生跳号时关闭链路，避免将不连续参考送入消回声 |
| 播放回答 | 主机 → 设备 `turn(turnId)`，随后 `speaker(turnId, seq, pcm)` | 24 kHz 单声道 PCM16 小端，每帧 960 字节，每一答从序号 0 开始。异步产生的音频始终携带原连接和回答编号 |
| 正常播完 | 主机 → 设备 `end(turnId)`，设备 → 主机 `played(turnId)` | 主机已发完全部帧；设备须等播放队列及硬件输出排空才回执 |
| 插话取消 | 主机 → 设备 `cancel(turnId)`，设备 → 主机 `stopped(turnId)` | 设备须停止该答、清除尚未输出的声音和表达。主机在匹配回执前阻止下一答播放，仍可接收当前采集。取消优先于正在等待的自然播完 |
| 断连 | 双端作废当前连接 | 主机关闭旧采集与回答。正式固件还须在本机停播并丢弃旧声音、字幕和动作。重连重新握手，由会话层决定何时重新开启收音 |

状态机默认给就绪及停播回执各 **5 秒**。自然播完的保守等待上限为已发音频时长加 5 秒。联调脚本将基础超时缩短至 1.5 秒以重放失败场景。PRD 对插话的 **1 秒**目标从本人起声算到旧音真正停止，需单独计时。
