# P1 转写歧义确认规则

状态：v2 歧义自动判断未通过；v3 已启用首次项目名确认规则。仍未实现结构化确认状态机或长期记忆写入。

目标是避免把名称和动作的错误断句当作确定事实。不能依赖某个项目名的字符串替换，也不应每次复述用户所有信息。

| 情况 | 对话行为 |
| --- | --- |
| 首次接收用户自己的项目名 | 用一个短问题确认准确名称；即使转写看起来通顺也确认一次，不以“记下了”代替确认 |
| 名称与动作连在一起、存在两种合理含义 | 只问一个短确认，例如询问哪些词属于名称；确认前保持不确定，不假装保存 |
| 用户明确纠正名称或时间 | 接受纠正，本次上下文使用新信息；用户要求仅给结果时不附加建议 |
| 已确认过项目名，或普通闲聊/未给名称的任务 | 自然接话，不逐项盘问、不重复确认 |
| 用户不愿确认 | 保留不确定性，不替用户做唯一选择；不执行相关操作 |
| 用户要求保存、安排、提醒 | 说明当前仅本次聊天上下文可用；未接入对应工具时不承诺执行 |

原始转写保留在诊断日志中，不能把模型修正后的推测覆盖成“原始识别结果”。这项规则目前由模型遵循，无法保证所有歧义都会被发现；需要真实麦克风体验确认是否过度追问。后续若接入记忆写入，应独立保存候选值、确认状态、用户纠正与来源，而非直接将模型回复当作已确认事实。

本轮回归先给出没有清晰名称边界的输入，再明确纠正并更改时间，最后要求仅说名称和最新时间。判定确认是否恰当、纠正是否生效、是否无端承诺保存，不能仅检查最终出现了正确关键词。
