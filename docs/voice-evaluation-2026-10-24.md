## 证据边界

- 三次复用相同合成声音，不是三种口音或三个真人独立样本；合成器与被测服务同源，也可能高估表现。
- 这些案例主要来自已知失败；问名字、咖啡等已在提示中出现。修改安排是新增检查，但整个小样本都不能作为广泛泛化能力证明。
- 当前程序等待生成完成再送下一问，没有覆盖真人抢话、背景噪声、长停顿或语音韵律。
- 真人“What's your name”和“What's your last answer”识别文本正确却答非所问的记录继续有效，状态仍为未解决。跨会话长期记忆尚未实现与本次同会话问题无直接解释关系。

## 两条语音路线的判断

| 维度 | 现有 Seeduplex | ASR → 文本 LLM → TTS 候选 |
| --- | --- | --- |
| 理解与上下文 | 已有真人失败；合成诊断未复现 | 可明确检查发给模型的文字与历史；质量待真实 API 对照 |
| 语言与自然度 | 顺序语言切换通过；真人中文插话失败、机械感未验收 | 可独立调节对话和音色；并不保证更自然，韵律信息可能损失 |
| 延迟 | 已有首音频收包测量 | 多一段生成/合成串联；需要流式输出与分句后实测 |
| 打断 | 原型实现取消与清空；用户确认基本体验符合 | 必须取消 LLM、TTS、播放并拒绝旧轮结果，不能直接继承现有通过结论 |
| 记忆/搜索 | 还需验证注入、工具与新问题优先机制 | 显式历史更易审计和插入工具结果，但需自行维护一致性 |
| 工程量 | 已有可运行页面 | 本轮仅完成文本对照程序；独立 ASR/TTS、流式播放与打断未实现 |

先比较“理解层”可以避免在质量无优势时先建设整条备用链路。对照程序使用本轮 Seeduplex 的最终识别文本、同一份系统提示，每个案例单独保存文本模型自己的历史。不把 Seeduplex 的答案塞给文本模型；复述问题应复述它自己的上一答。未使用独立 ASR，因此这仍不是两套完整语音方案的公平端到端比较。

首选对照候选 `doubao-seed-2-1-turbo-260628`，关闭深度思考，单次输出上限 512 token。该版本在官方模型清单中；非流式调用用于先判语义，程序记录完整回答耗时，不将其与 Seeduplex 首音频耗时直接比较。[模型清单](https://docs.volcengine.com/docs/ark/model-list?lang=zh)、[Chat API](https://docs.volcengine.com/docs/ark/chat-api?lang=en)

## 下一步与停止条件

1. 用户只需准备标准方舟文本 API 凭证，见 [最小开通说明](ark-evaluation-setup.md)。当前语音凭证与该凭证分开，尚未验证独立 ASR/TTS 权限，不要求本轮提前开通。
2. 用同一份 42 轮识别文本完成对照；逐条检查问名字、复述、中文求助、信息更新、无效纠错及自然度。出现任何关键语义错误仍记录为候选风险，不用通过总数掩盖。
3. 文本模型表现有价值时再接独立流式 ASR/TTS，测真实首段有效声音延迟和插话。若无优势，检查更丰富上下文和提示冗余，再追加未见过的案例，而非直接换架构。
4. 两条路线有完整链路证据后，再给用户安排短小真人对比；暂不要求重测，也不启动硬件采购。

本轮本地自动化 17/17 通过，包括上下文隔离、失败不污染历史、并发轮次拒绝、PCM 转换及既有播放取消回归。文本模型尚未调用，缺凭证时已验证程序在发出网络请求前明确退出。
