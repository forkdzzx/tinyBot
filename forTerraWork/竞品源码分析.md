# Jarvis 竞品源码参考

记录日期：2026-10-29。用途：供项目监工会话只读分析参考，不代表项目实施决定。

## 结论

优先参考 m5-robot-companion 的头部动作反馈与取消设计，StackChan Gemini 的动作编排，以及小智的设备状态转换。ElectronBot 的表达协同和故障隔离已有项目内固定版本审查。没有证据证明这些项目可以直接满足 Jarvis 全部 V1 验收。

## 源码发现与 Jarvis 的关系

### m5-robot-companion

[motion_tools.py](https://github.com/regitxx/m5-robot-companion/blob/main/motion_tools.py) 对动作参数做范围检查、查询位置反馈、限制等待时间；查询可重试而动作不重放，并通过停止标记及设备 stop_epoch 取消当前轮动作。可供 Jarvis T-49～T-51 设计参考。参数、释放扭矩的安全性以及反馈能力必须按实际结构验证；没有反馈时不能声称实际到位。

Jarvis 当前 `prototypes/expression/state.mjs` 用轮次号使旧表达失效，但动作仍是模拟；尚需把同一语义接入真实控制设备。

### StackChan Gemini

[ServoGestureController.cpp](https://github.com/taranton/stackchan-gemini-firmware/blob/main/src/ServoGestureController.cpp) 将动作表示为有限步骤，支持相对姿态锚点，停止时清空步骤并调用底层停止。适合参考预设动作和队列组织；尚未证明语音、字幕、表情、动作能够整轮同步取消，或实际电机平滑减速。

[EmotionController.cpp](https://github.com/taranton/stackchan-gemini-firmware/blob/main/src/EmotionController.cpp) 根据倾听、说话、思考、睡眠等状态渲染视觉效果。Jarvis 仍需实现和验证表情进入、保持、退出、字幕空间及打断优先级。

[MemoryStore.cpp](https://github.com/taranton/stackchan-gemini-firmware/blob/main/src/MemoryStore.cpp) 将事件、对话、事实和摘要分开，事实保留来源与置信度。可对照检索和数据分类；不能从追加写入推断断电恢复和完整冲突确认已达标。Jarvis 已有来源验证、原子替换、待确认状态和后台任务恢复，不建议仅因上游具备记忆功能就替换。

### 小智 AI

[device_state_machine.cc](https://github.com/78/xiaozhi-esp32/blob/main/main/device_state_machine.cc) 定义设备状态及合法转换，向监听者通知状态变化。可参考设备交互边界。Jarvis 的勿扰、模式、主动搭话抑制、等待和电源状态需能同时存在，不能只照搬单一状态枚举。音频和打断的完整调用链尚未审查完毕。

### ElectronBot

已有 [项目内固定版本审查](../prd/electronbot-review.md)，涵盖画面与姿态协同、表情过渡、通信阻塞、关节映射及最小自检；还记录了 SDK 缓冲区、无限等待和平台依赖风险。该报告的审查版本为 `819927015323181a9a10e0184d64ad2bddfcb407`。优先借鉴设计与分模块测试，不直接依赖未经修正的 SDK。

### StackChan 官方固件及 Reachy Mini

[StackChan 官方固件](https://github.com/m5stack/StackChan/tree/main/firmware) 包含硬件抽象和设备代码，需在确定硬件候选后进一步追踪音频、控制和电源路径。[Reachy Mini 运动模块](https://github.com/pollen-robotics/reachy_mini/tree/main/src/reachy_mini/motion) 将目标运动、录制动作和说话动作分开；尚未完整追踪到电机执行和取消，不能推断满足 Jarvis 验收。

## 建议的后续阅读顺序

1. 对照 K151 设备协议，核查双向音频、打断停播、控制板连接与重连；判断 A2 路线可行性。
2. 结合动作反馈、超时、失效编号和硬件故障策略，准备两轴设计比较。
3. 核查表情渲染及动作队列与实际音频事件如何协调。
4. 比较记忆检索及冲突确认机制，优先处理已有真人短测问题。

## 证据边界

除 ElectronBot 的固定版本审查外，本次是通过 GitHub 网页静态阅读部分关键文件和目录，其他链接指向可变的 main 分支，并未固定提交；没有编译、刷写、运行或进行完整仓库审计，也没有验证成本、网络可达性或实机表现。许可证标示需在具体复用时结合文件与依赖单独核查。
