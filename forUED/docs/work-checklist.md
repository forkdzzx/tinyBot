## 2. 清单怎么读和维护

| 状态 | 含义 |
| --- | --- |
| ✅ 已完成 | 该行明确限定的工作已有产物与证据；例如“资料审查完成”不表示实机通过 |
| 🟡 部分完成 | 已有实现或证据，仍有该行列出的缺口 |
| 🧪 待验证 | 此项实现已经具备，尚缺对应真人／实机或正式次数的验证 |
| ⚪ 未开始 | 需求已明确，尚未完成对应实现或实测；写入 PRD 不算完成 |
| 🔷 待决策 | 已有候选，尚需补齐比较条件后确定选择；不表示现在就要求你拍板 |
| ↪ 已延期 | 经你同意移出 V1 主流程，保留原因、证据与后续入口，不计为完成 |

默认分工：我负责分析、文档、软件与可执行检查；你负责体验反馈、重大方案取舍、采购付款、接线装配和现场硬件操作。各行补充具体配合时机。

- **固定编号不复用。** 新任务追加编号；拆分时保留原项及关联项。删减、替换或延期保留去向与原因。
- 每次有实际进展、测试反馈或范围变更，更新相关状态、剩余工作、证据链接和顶部日期，并在第 6 节记录变化；不因日期推进自动标完成。
- 已完成的是文档、模拟、合成回环、真人体验还是实机验收，必须写清。旧失败记录不被后来的少量成功覆盖。
- 本文维护当前工作状态；[PRD](../prd/prd-v1.1.md)定义需求与验收，[计划表](../prd/project-plan-v1.md)定义阶段，[进展记录](project-status.md)保留详细过程，[V2 备忘录](../prd/v2-iteration-memo.md)记录延期需求。范围变化同步这些文件，不仅改一个勾选。
- 你可以直接说“更新 T-18 的结果”“把 T-42 提前”或指出遗漏；我会结合依赖调整清单，不要求你维护技术细节。
