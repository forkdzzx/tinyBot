## 1. 设计结论与已确认偏好

**Jarvis 的脸是一对有性格的眼睛：眼形表达态度，节奏表达语气，状态与文字说明它正在做什么。** 不用一段完整视频包办所有状态，也不依赖不断切换颜色来区分情绪。

用户在首轮预览后明确提出四项整改，本版据此替换旧方案：

1. **不同表情和模式要有各自的特别设计。** 轮廓、运动方式和符号组合都需要区分，不能主要靠名称、颜色或幅度小改。
2. **眼形更灵动、多元。** 圆形、竖豆形、断环、方框、星形、心形、泪滴、钻石、笑弧和折线等共同组成词汇；长条眼只用于半眯、困倦等有明确含义的情况。
3. **整体偏活泼。** 用户撤回“克制”的描述，工作模式也有鲜明、活跃的视觉表达，不再整体降档成低动作版本。
4. **允许更多情绪符号，强情绪可以满屏演出。** 兴奋可使用星轨、彩带和放射线，喜欢可使用心形轨道；同时保持字幕、插话和关闭行为正确。

变更记录：v0.1 的“日常活泼、工作克制”“少量符号、避免满屏特效”是已被用户撤回的旧偏好，**不再作为当前设计约束**。保留的是明确勿扰、安静等待等业务语义，以及工作受挫时不嘲笑用户；它们不等于要求整个人格安静。

继承已确认要求：伊娃式双眼、没有嘴巴也成立；理性、幽默、略带吐槽；工作受挫时减少玩笑；眼睛下保留一两行文字；20–50 cm 使用；本地动画；允许中断；两轴动作可关闭。本文的幅度、时长、帧率和文字尺寸均为**待体验／实机验证的起始设计值**，不自动升级为新的 PRD 硬指标。

“心情”在这里指 Jarvis 对当前对话采用的表达态度，例如欣喜、关切、好奇、迟疑，不表示模型具有人类情感，也不表示它通过摄像头识别了用户情绪。用户说“今天很烦”可触发关切；一句话里出现“难过”两个字，不足以自动播放难过表情。

## 2. 从 emotion-ball 借鉴什么

审阅版本：[`e09d114d40888e24afc394098cd3f09b0a258d8c`](https://github.com/Aithena/emotion-ball/tree/e09d114d40888e24afc394098cd3f09b0a258d8c)。详细源码证据另见审阅报告。

| 原项目机制 | Jarvis 的采用方式 | 需要改变的部分 |
| --- | --- | --- |
| 几何、表情配置、渲染、驱动分层 | 眼形模板、表达配置、状态裁决、渲染分别维护 | 不让模型直接操作绘制器或电机 |
| 等量轮廓点平滑形变 | 用统一拓扑的原创双眼路径，平滑改变开合、弧度和左右差异 | 采用原创多家族轮廓；异构形状可做短过渡，不搬用原眼环坐标 |
| 小眼形池＋循环动画 | 同一情绪允许两三种细微变化，避免每次同一个眨眼 | 变化必须保持语义；倾听不能随机轮换为怒目或笑脸 |
| 关键帧＋收尾语义 | 一次性惊讶、轻笑有进入、保持、退出；等待循环有结束条件 | 收尾返回**当前业务状态**，不能统一回待机 |
| 同一个本地动画时钟 | 用经过时间驱动形变，离屏暂停；低性能屏幕降级 | 状态时钟与动画时钟分开，恢复窗口不能补播过期动作 |
| 小尺寸精简显示 | 先保眼形与文字，再关辉光、符号和细节 | 不直接将整颗球缩小到机器人屏幕 |
| AI 给出有限表达编号 | 模型可给出可校验的情绪意图 | 编号不是“系统正在听／已保存／已关机”的证明 |

原项目的球体、球面投影和鼠标跟随不进入 Jarvis V1 的默认脸面。Jarvis 已有实体身体，无须再在屏幕内画另一个身体。v0.2 重新采用彩带、星轨、粒子等屏幕演出思路，使用自主绘制和调度；它们可以覆盖整个脸屏。屏幕内旋转或弹跳不映射为实体自旋或蹦跳。原项目的固定周期说话动画不能用作实际音频同步依据。

源码审阅报告保留首轮的取舍历史；其中“克制／不采用彩带”等产品建议已由本版用户反馈更新，源码事实与许可结论不受影响。

本轮预览为独立编写的几何和动画，不嵌入原仓库脚本、眼环坐标或素材。原仓库文档描述双许可，但固定版本缺少其引用的根 `LICENSE`，不按 MIT／Apache 等通用许可假定可任意移植；后续如要直接使用其源码，应先补齐相应授权信息。此项不阻碍当前自主实现的设计研究。

## 3. 一张脸，四层信息

不要维护一个同时包含“开心、关机、勿扰、英语模式”的巨大互斥枚举。合成时按以下四层处理：

| 层 | 负责什么 | 控制来源 |
| --- | --- | --- |
| 运行状态 | 关闭、待机、连接、倾听、思考、搜索、播放、等待、停止 | 本地会话、播放器、网络及电源实际事件 |
| 表达态度 | 中性、好奇、开心、兴奋、大笑、喜欢、自豪、坚定、鼓励、共情、疑惑、惊讶、轻吐槽 | 对话语义或有限本地规则；可缺省为中性 |
| 模式与属性 | 四种模式、勿扰、故障、是否允许符号／动作、减弱动画 | 本地配置和已生效的业务状态 |
| 短时演出 | 眨眼、符号群、满屏庆祝、轻点头、惊讶峰值 | 表达调度器，绑定轮次／片段，有时限 |

例如“说话＋鼓励＋英语模式”仍显示正在播放；说完回到温和倾听。“勿扰＋倾听”仍有专注双眼，只保留小型勿扰标记，不会因为勿扰闭眼不理用户。“运动故障＋说话”可以继续眼神和音频，只禁用出故障的动作。

**眼神的主次：运行事实先成立，态度再修饰，装饰最后加入。** 云端没有表达元数据时，聊天依然完整；状态丢失时保守显示连接／等待，并给出文字说明，不能编造成功。

## 4. 视觉语言与屏幕布局

### 4.1 Jarvis 的识别特征

- 以黑色脸面和发光双眼维持 Jarvis 身份；青蓝为常态基色，情绪与模式可引入金黄、紫粉、绿色等辅助色。轮廓变化先于换色，去掉颜色仍应看得出差别。
- 默认从饱满圆眼／竖豆眼起步，不再以扁长椭圆作为大部分状态的母版。连接使用断环，搜索使用方框，兴奋使用星眼，喜欢使用心眼，共情使用泪滴，下垂和长条仅保留给困倦、吐槽等特定语义。
- 一种表情至少有一项独特的轮廓特征和一项独特的运动／符号特征。例如“好奇”是一大一小的圆眼配探索气泡，“惊讶”是成对圆环配放射线；二者不再只是同一眼形放大不同倍数。
- 允许明显的不对称、单眼眨动、弹性挤压、视线跳转和短暂旋转，让眼睛本身参与表演；眼睛始终成对建立脸部方向，不额外添加鼻子或嘴巴。
- “看向一侧”是角色动作，不表示真实看见物体。V1 不按摄像头目标或鼠标位置驱动产品视线。
- 四种模式各有可辨的默认眼形、专属符号和动作编排，见第 6.3 节。模式差异不是仅给同一张脸调节活跃度。
- 辉光、粒子和符号可关闭；关闭后仍保留星眼、心眼、圆眼、框眼等几何差异。

### 4.2 布局基准

设计用归一化坐标描述，宽 W、高 H。眼睛位于上中部，字幕与状态位于下方固定区域；字幕区域保持稳定；眼睛可以在上方表演区弹跳和伸展，不能带着文字一起跳动。满屏特效可经过整个屏幕，字幕在更高图层独立保持清晰。

| 区域 | 方屏起始布局 | 320×240 横屏适配 |
| --- | --- | --- |
| 外边距 | 左右至少 6% W，上下至少 5% H | 左右至少 12 px；保留实际屏幕裁切余量 |
| 眼区 | 约 y=18%–65% H；中心约 (33%,40%)、(67%,40%) | 眼区约 y=32–155 px，按比例重排，不拉伸方屏画面 |
| 基础眼形 | 圆眼直径约 18%–23% W；豆眼可高于宽；星／心／钻石按各自包络布局，预留弹跳和放大空间 | 分别保持轮廓纵横比；圆形不能压成椭圆，符号独立重排；最低闭眼线至少 2 px |
| 字幕区 | 约 y=76%–92% H，最多两行 | 约 y=173–224 px，两行约 20 px 字号、24 px 行高 |
| 状态标记 | 右上预留一处短标记，位于眼区之外；错误解释仍在下方字幕区 | 小屏可与下方首行短状态合并，空间不足时优先文字 |

720×720 仅是候选方屏的分辨率样例，建议从 32–36 px 字号试起；320×240 从 18–20 px 试起。不得机械地把字号按 320/720 缩小。当前预览中的“320×240”只展示横屏比例、留白及独立字幕排布，实际绘制仍会随浏览器大小缩放，**没有验证精确 320×240 栅格／字号，也不能证明 2 英寸屏幕在 50 cm 可读**。若小屏在实际观看距离无法兼顾两行文字与眼睛，应调整屏幕／安装位置或由用户明确接受妥协，不默默删除字幕要求。

### 4.3 字幕与符号

字幕优先级：阻塞交互的错误／恢复提示 > 正在播放的回答片段 > 当前识别结果 > 简短常态说明。必要的收音、勿扰或连接标记保留，但不堆成状态仪表盘。

- 识别中允许覆盖更新同一行，暂未确认的文字用稳定的“听到：”或弱样式区分；最终结果替换，不每个 token 追加新行。
- 说话时按播放片段更新字幕。不能提前把云端已生成但尚未播出的全文快速滚完。
- 中英文按语义断句；英文尽量不断开单词，长技术词超出单行时换行／截断并保留完整本地历史，不缩小到难以辨认。无需触摸编辑和历史浏览。
- 未获得逐字时间戳时采用片段同步，明确不是卡拉 OK 逐字同步。必要时短摘要作为辅助文字，不能误标成逐字转写。
- 插话立即清空旧回答字幕；新 ASR 未到时可显示“正在听”。等待期间的字幕不应一直保留前一轮错误结论。
- 符号成为表情的一部分：疑惑可出现问号群，思考有逐个冒出的气泡，工作有代码括号／游标，英语有对话泡泡／字母，开心有星点，喜欢有爱心。可以同时有多个符号，不再采用“最多一个”的通用限制。
- 兴奋等强情绪允许满屏星轨、彩带、放射线和粒子。眼睛保持在最前的主要视觉层；字幕区使用独立前景／底衬，使粒子经过时仍能读字。
- 工作模式不关闭符号和演出；其装饰使用技术、灵感和完成感语言。工作受挫时切为共情／鼓励的对应演出，不继续无关庆祝或嘲笑。
- 明确的勿扰待机、安静等待与关机按业务要求降低或停止自发表演；这是状态行为，不是全局审美方向。用户主动聊天后仍显示该模式的独特眼形。
- 强情绪演出可手动重播，正式接入时绑定具体事件；同一流式回复片段重复到达不重复炸场。取消、换状态、关闭交互会清除旧符号和粒子。
- 勿扰、麦克风未就绪、错误不能只靠颜色表达，配短文字或明确图形。

## 5. V1 眼神词汇表

下表中的时长为视觉建议，不改变 PRD 的 2 分钟沉默、10 分钟等待、15–20 分钟主动搭话与 30 秒应答窗口。循环表情随业务事件退出；一次性情绪完成后恢复实时状态，不自行开始或结束会话。

### 5.1 运行状态

| ID／状态 | 独特眼形 | 专属动态／符号 | 字幕及边界 |
| --- | --- | --- | --- |
| `disabled`／`off` 未启用／关闭 | 整个屏幕黑，所有眼形和图层隐藏 | 立即停止粒子、光环、字幕与模式装饰 | 黑色绘图不等于背光断电，需电源层实现 |
| `idle` 待机 | 当前模式的标志眼形：日常圆豆／工作棱角／陪伴星眼／英语竖豆 | 模式专属眨眼、回弹和周边符号 | 默认不暗示正在收音；实验唤醒开关另行标识 |
| `connecting` 连接中 | 一对有缺口的发光环 | 双环错相旋转，短链路符号逐一出现 | “连接中，请稍候”；未就绪不能显示“我在听” |
| `listening` 倾听 | 在当前模式眼形内睁开／聚焦；日常是饱满圆瞳，工作保留棱角、陪伴保留漫画感、英语保留竖豆 | 接收弧从两侧向眼睛收拢；新输入时有一次关注动作 | 本地输入反馈目标 ≤300 ms；转写与正在听状态一致 |
| `thinking` 思考 | 一只豆眼配一只思索环，组合明显不对称 | 眼睛上看，气泡依次生成／消散，停顿后换一次方向 | “想一想”；不冒充搜索已启动 |
| `searching` 搜索 | 成对方框／取景框眼 | 扫描光和探照轨迹在框内移动，检索符号划过 | 只有实际任务启动才显示“查询中”；不虚构进度百分比 |
| `speaking` 说话 | 当前模式的饱满眼形附当前情绪特征；日常以豆眼示例，其他模式保留各自骨架 | 挤压回弹、左右呼应及声波；实际接入后跟随短语／播放包络 | 实际播放开始进入，同片段字幕；不逐字点头 |
| `waiting` 安静等待 | 柔软的等待眼形，保留模式辨识元素 | 眼形慢呼吸，暂停外向邀请动作 | “等一下，我想想”生效即进入；最多 10 分钟，不催促 |
| `inviting` 主动邀请 | 一圆一眨的招呼姿态 | 关注波纹与一次招呼动作，播完转倾听 | 30 秒允许直接回应；无回应回待机并抑制再次邀请 |
| `drowsy` 困倦 | 月牙／下垂眼，明确区别于正常睁眼 | 慢闭合和睡意符号；仅待机阶段进入 | 空闲建议 5 分钟后出现；不表示关机或断网 |
| `closing` 停止／关机过程 | 立即切到 off 全黑 | 当帧清除眼形、字幕和演出 | 立即停止交互；关机完成全黑；不借动画假定数据已保存 |

### 5.2 情绪与语言态度

普通情绪可以保持活跃循环，强情绪先有进入演出，再回到仍有生命感的保持姿态。强烈的表现服务于当前内容，而不是每段话机械重播同一套庆祝。

| ID／态度 | 独特眼形 | 动态／符号与适用场景 | 语义边界 |
| --- | --- | --- | --- |
| `neutral` 中性 | 使用模式基础眼形，饱满而清晰 | 保留该模式特有的待机动作和符号 | 没有情绪信号时仍可活泼，不伪造情绪判断 |
| `curious` 好奇 | 一大一小的圆眼 | 两眼先后探向一侧，探索气泡／问号轮换；用于追问经过 | 倾听开始后将关注收回，不表示发现现实物体 |
| `happy` 开心／认可 | 上拱笑弧眼 | 双眼弹跳、星点绽开；“这次终于过了，漂亮。” | 实际写入前不能用成功演出承诺已保存 |
| `excited` 兴奋 | 成对星形眼 | 星眼放大回弹，满屏星轨、彩带和放射线；适合过关／逆转等强烈好消息 | 以用户口述或已确认事实触发，不能猜比分后庆祝 |
| `laughing` 大笑 | 挤笑折线／尖弧眼 | 双眼错相起伏，笑声字样与笑波扩散 | 跟随真实幽默语境；用户受挫时不使用 |
| `love` 喜欢／喜爱 | 成对心形眼 | 心形呼吸、爱心轨道和漂浮心符号；表达“这设计真讨喜” | 用于喜欢的事物或话题，不强制每次称赞都冒爱心 |
| `proud` 自豪 | 钻石／菱形眼 | 上扬姿态、勋章和明亮弧线；表达完成挑战的成就感 | 对有事实依据的进展使用，避免每轮都自夸 |
| `determined` 坚定 | 火焰形眼 | 火苗跳动、目标箭头和向上冲线；“这次我们把它解决。” | 热情不替代能力或结果保证 |
| `encouraging` 鼓励 | 明亮的上扬眼与轻单眨组合 | 上升箭头／加油星点、向前提起的节奏；鼓励继续尝试 | 不对每个英语词都强行欢呼；用户说先等一下就停止催进度 |
| `empathetic` 难过／共情 | 泪滴／柔软下垂眼 | 缓降水滴和柔和环绕，姿态有明显下沉感 | 关注用户的困难，不因用户不回复而扮委屈 |
| `puzzled` 疑惑／需确认 | 一圆一折、一大一小的不对称眼 | 两眼交错抬起，问号群依次出现 | 需要澄清时使用；不把所有设备故障都画成疑惑 |
| `surprised` 惊讶 | 成对圆环／圆睁眼 | 瞬时睁大、短暂停住，外侧放射惊叹线 | 只对已知内容回应；坏消息不做庆祝式爆发 |
| `teasing` 轻吐槽 | 一只压低半眯眼＋一只挑起眼 | 单眼眨动、斜向偏移、漫画省略号；轻松调侃操作 | 工作受挫／明确不喜欢／不确定语境时禁用 |
| `considering` 迟疑／审慎 | 一侧略压低、另一侧保持圆眼 | 短停、视线回看和省略号；“我倾向这个原因，还需要看日志。” | 区别于系统计算中的 thinking，不假装结论确定 |

兴奋、大笑、喜欢、好奇、自豪、坚定六种新增表情与原基本眼神共同构成 v0.2 预览词汇。愤怒、恐慌、羞涩等后续可继续扩展；本版不为了复刻原项目编号而添加没有明确使用场景的表情。

### 5.3 叠加属性与异常

| 属性／事件 | 视觉处理 | 不能发生的误导 |
| --- | --- | --- |
| 勿扰开启 | 待机更安静；小标记＋“勿扰”；主动发起会话后照常倾听／说话 | 不把它画成关机，不因一次聊天或换模式自动取消 |
| 网络／云服务不可用 | 眼睛保持柔和稳定，文字“连接中断，正在重连”或准确错误 | 不继续“思考”无期限等待，不假装还能离线对话 |
| 恢复联网 | 取消错误标记，回到真实可用状态 | 不突然播完断网前的旧回答；是否重建云会话由业务层确认 |
| 听不清／识别停滞 | 短疑惑后稳定倾听，文字说明“没听清，请再说一次”或已有恢复入口 | 视觉层不把 partial 当最终结果，也不另加抢话计时器 |
| 记忆待确认 | 温和疑惑／中性，显示准确确认问题 | 不用完成亮点提前承诺“已保存” |
| 保存成功／失败 | 收到实际成功回执后短认可；失败用文字并保持中性 | 后台普通记忆整理仍静默，不每次做庆祝动画 |
| 关节失联 | 停该关节，眼睛与音频尽量继续；短状态后可保留小标记 | 不把下发角度当实测到位，不让脸“死亡” |
| 未知表达 ID／渲染降级 | 丢弃无效情绪，保留真实运行状态与中性眼形，记录原因 | 不能一律回待机覆盖还在说话的事实 |

## 6. 动画语法：像在回应，而不是播放表情包

### 6.1 多家族几何与演出配置

生产实现建议以 `shapeFamily / shapeParams / left / right / pose / motion / symbols / burst` 组织数据：

- **轮廓家族**：圆／豆、断环、框、星、心、泪滴、钻石、火焰、弧和折线。每个家族有自己的几何生成方式，不继续以一个长椭圆的宽高解决全部表情。
- **双眼关系**：大小差、开合错拍、视线汇聚、左右轮流弹跳、单眼眨动。日常动作和情绪关键帧均由配置指定。
- **循环动作**：呼吸、回弹、环转、扫描、眨眼、气泡、波纹；每个状态选择自己有意义的组合。
- **进入演出**：例如兴奋的星眼弹出＋彩带扩散；惊讶的圆睁＋短暂停；喜欢的心形变换＋爱心绕行。
- **收尾与取消**：过渡回当前运行状态；插话或关闭直接撤销旧特效队列。状态变更时从当前显示姿态衔接。

同拓扑轮廓可插值；星、心、环等异构形状可以用短淡变／展开过渡，不能为了统一插值强行把它们全部近似成长条。单位用归一化比例，像素和字体由屏幕适配器转换。缩放只影响演出大小，不代替轮廓设计。

### 6.2 起始节奏建议

| 动作／演出 | 设计节奏起点 | 差异要求 |
| --- | --- | --- |
| 日常眨眼与视线 | 约 3–6 s 发生一次眼神动作，包含单眨、双眨、探看；闭合约 100–180 ms | 有静有动，动作不是所有状态相同的正弦平移 |
| 角色呼吸／弹跳 | 约 2–4 s 一轮，配眼高和位置的弹性变化 | 日常圆豆弹性、工作眼有精准卡点、陪伴有漫画回弹、英语用轮流应答 |
| 思考 | 约 1.5–2.5 s 的气泡序列和上看停顿 | 轮廓、视线与气泡形成同一段动作，不与搜索共用扫视 |
| 搜索 | 约 1.2–2 s 扫过一次，短停后反向 | 框眼与扫描光明确区别于连接中的环形旋转 |
| 普通情绪进入 | 约 160–450 ms；先形成可辨轮廓，再加入符号 | 同态重复不强制重播；明确“重播演出”可再次完整观看 |
| 惊讶 | 约 120–180 ms 达峰，短暂停后回落 | 快起、停顿、回落，与开心的连续回弹不同 |
| 兴奋满屏演出 | 约 3.6 s：星眼弹出 → 星轨／彩带展开 → 粒子散去 → 星眼保持 | 有明显开场、高潮和收尾；多个符号可同时覆盖屏幕 |
| 说话律动 | 播放中按短语挤压与恢复，句间可单眨回应 | 实际接入后跟随播放；不让每个字都触发同一个动作 |

工作模式不再统一减小上述幅度或拉长眨眼间隔。它使用自己的动作语言：代码块节拍、游标跳动、轮廓卡点和灵感闪现；仍然活泼。安静等待、勿扰待机等明确状态保留安静语义。

### 6.3 四种模式各自的造型

| 模式 | 默认轮廓 | 专属符号与舞台语言 | 动态识别点 |
| --- | --- | --- | --- |
| 日常 | 圆眼／豆眼，左右有弹性差异 | 招呼波纹、星点、好奇气泡 | 单眼眨动、短探看、柔弹回中，像随时愿意聊的朋友 |
| 工作 | 角方／六边形眼，边角清晰 | 代码括号、游标、逻辑节点或灵感符号 | 精准跳位、短扫描、完成时展开；活泼而有条理，不是“少动版日常” |
| 陪伴 | 星形／漫画眼 | 游戏星轨、漫画速度线、彩带和成就符号 | 大幅回弹、左右呼应、事件发生时短高潮，适合游戏／看球陪聊 |
| 英语练习 | 竖向豆形／应答眼，开合有轮流关系 | 对话泡泡、字母或短音节元素 | 一问一答式轮流弹出、鼓励式单眨，让练习像互动游戏；不自动把普通英文当练习 |

同一个“待机”并排展示四模式时，不看标签也应有明显轮廓或构图差别。强情绪可暂时使用通用星眼／心眼等图形，模式通过周边符号和动作韵律继续体现；不能为了模式身份削弱情绪本身。切换模式有一次短造型转换，不等待转换完成才允许聊天。

### 6.4 满屏演出与两轴配合

满屏是**机器人脸屏内**的演出，不要求电机大幅运动。兴奋可使用多层星轨、彩带和放射粒子，喜欢可使用心形轨道，大笑可用漫画笑波；状态和字幕作为最上层内容保持可见。由本地演出模板决定形状、数量和时长，不让模型任意添加图元或无限延长。

实际接入时，强演出关联同一 `eventId` 与轮次；进入一次，不因流式文本重复炸场。插话、会话结束、黑屏和切换表情立即清除旧粒子；不能在新一句里继续飘旧庆祝彩带。预览提供“重播演出”，方便用户完整查看短高潮。

眼睛可先于实体姿态约 80–150 ms 发出信号，不等待电机到位才允许音频或倾听。认可／鼓励可点头，疑惑可转向，惊讶可抬头，共情可低头；是否执行取决于实际硬件限制。机械限位、承重和动作频率仍由 T-49／T-50 校准，**不把机械保守参数变成眼睛必须克制的理由**。屏幕内弹跳或旋转不对应实体跳跃、自旋或新增侧倾关节。

## 7. 调度、优先级和语音接入

### 7.1 先处理事件，再渲染

建议链路：

```text
会话／收音／播放／工具／电源事件 → 本地表达裁决器 → 当前脸面参数 → 屏幕
                                       ├→ 同片段字幕
对话情绪意图（可选） ────────────────────┘
                                       └→ 有限动作预设 → 限位／限速控制器
```

裁决顺序：关闭交互／关机 > 会话结束、插话与轮次失效 > 阻塞性故障和恢复事实 > 当前收音／播放／等待事实 > 语义态度 > 自发微动作／装饰。非阻塞性关节故障只影响相应能力，不抢走整张脸。

同时收音和播报不直接叠两张表情；检测到有效插话后取消当前输出，转倾听。判断插话的仍是既有语音链路，不在视觉层再加一套声学判定。

### 7.2 最小表达事件契约（设计，尚未接入）

```json
{
  "version": 1,
  "sessionId": "session-example",
  "turnId": 12,
  "responseId": "response-example",
  "segmentId": "segment-2",
  "eventId": "expression-12-2",
  "source": "dialogue",
  "tone": "encouraging",
  "intensity": 0.45,
  "motion": "nod_small",
  "ttlMs": 3000
}
```

- 业务运行状态由本地事件确定；这个模型候选事件不能设置 `listening`、保存成功或关机完成。
- 接收时本地打单调时钟时间戳，不信任云端时钟；`ttlMs` 是调度器限制后的候选有效期，不是必须完整播放的长度。
- 限定 tone／motion 白名单、有限数值及幅度范围、短时上限；未知字段忽略或记录，非法值回退中性，不执行文本脚本。
- 必须匹配当前 session／turn／response。同 eventId 幂等，同态更新不重放。换题、结束和重连使旧事件失效；跨会话不能靠重用 turnId 混入。
- 尚未开始的片段意图最多保留一条待触发；更新替换旧候选。播放开始时再次检查所属关系及有效期，过期直接丢弃，不能排成几秒长表情队列。
- 语义元数据晚于该片段开始到达超过建议 300 ms，则本句保持中性，后续有效片段再用；不为了等待表情推迟声音。
- 先以确定的状态和少量本地语境为基线；模型结构化情绪输出属于后续接入步骤，**当前 Seeduplex 没有被验证会稳定返回此契约**。不增加一条阻塞音频的情绪模型调用。

### 7.3 现有代码的接入位置与缺口

| 当前位置 | 已有基础 | 需要补齐 |
| --- | --- | --- |
| `prototypes/expression/state.mjs` | 模拟轮次、打断和旧回答失效 | 只含基础互斥阶段；不是完整表情、真实播放或电源系统；保留其回归意义 |
| `prototypes/voice/client.mjs` | `face()` 状态调用、输入／响应事件、错误和结束处理 | 各处分散赋值需接到统一裁决器；不能直接用情绪覆盖状态 |
| `client.mjs` 的音频 `enqueue` 路径 | 收到 PCM 后入队并置 speaking | 目前入队即 speaking；需以 AudioContext 实际排程起点且正常运行作为更准确的播放开始依据，处理 suspended／缓冲情况 |
| `prototypes/voice/playback.mjs` | 排程、清理、onended 及回执 | 排程回执不等于已出声；补同片段可用的时间／开始事件。即使有开始事件，仍不能证明扬声器实际发声 |
| `prototypes/voice/lifecycle.mjs` | 2 分钟／10 分钟会话规则 | 视觉订阅已有规则，不另写冲突计时器 |
| 按钮结束与实验唤醒路径 | 基础 idle／实验路径的困倦计时 | 当前按钮主路径的困倦覆盖不足；统一待机计时后再接新眼神 |
| 搜索、主动搭话、勿扰、实体动作 | PRD 已定义 | 当前未完整接入；预览中出现这些状态只是设计演示 |

本轮不修改上述真实语音代码，避免用户读设计时引入新的语音测试变量。新增预览单独放在 `prototypes/eyes-design/`。

## 8. 关键情景分镜

| 情景 | 连续画面与语音关系 | 必须保持的行为 |
| --- | --- | --- |
| 按钮开始问 Java 问题 | 待机 → 本地关注／连接中 → 就绪倾听 → 思考 → 技术中性说话 → 倾听 | “收到答案”不提前演说话；状态文字始终解释等待 |
| 回答中插话 | 说话＋当前字幕 → 立即停旧音频／清字幕／撤旧表达 → 倾听 → 新轮回答 | 旧结果随后到达也不能再亮眼、点头或覆盖字幕 |
| 沉默思考后继续 | 倾听 → 用户要求等一下 → 稳定安静等待 → 用户开口后倾听 | 不演困倦催促、不主动总结、不倒计时施压 |
| 工作卡住 | 棱角眼倾听 → 共情泪滴眼 → 给建议时明亮鼓励 → 工作模式眼形 | 符号随语义由逻辑节点切为支持性图形，不做无关庆祝或嘲笑 |
| 英语找不到词 | 稳定倾听 → 中文求助后温和说明 → 用户恢复英文后继续 | 不用生气或错误脸评价口语；不在停顿时抖动催回答 |
| 游戏过关／比赛反转 | 用户口述 → 圆环惊讶 → 星眼兴奋＋满屏彩带／星轨 → 陪伴倾听 | 没有观赛画面能力；不能自行庆祝未确认比分；插话立即清掉庆祝 |
| 记忆冲突 | 温和疑惑＋确认问题 → 倾听 → 实际保存回执 → 短认可 | 用户没确认或保存失败时不出现完成暗示 |
| 主动邀请无人回应 | 一次好奇邀请 → 30 秒温和倾听 → 待机 | 无失落、哭泣或连续呼唤；业务层抑制再次邀请 |
| 勿扰期间主动提问 | 安静待机＋勿扰标记 → 正常聊天＋勿扰标记 → 安静待机 | 聊天、换模式均不清除勿扰 |
| 断网与关机 | 断网显示明确状态，脸本地可动；关机则停止交互并收尾，完成全黑 | 不把失联网路当人格情绪；关机不等待动画或云端提炼 |

独立预览用按钮和时间线示范部分分镜，不执行上述真实会话控制。完整场景将通过集成检查逐项验证。

## 9. 性能与降级

- Linux 浏览器候选：原创 SVG 路径／Canvas 均可；预览采用参数化曲线。先保持一个渲染实例和一个动画时钟，不为每只眼睛、每种特效创建常驻定时器。
- 渲染目标先定 30 fps；主控有余量再用 60 fps，低性能可降为 15–20 fps 的平滑少特效显示。这是候选目标，未在 Pi／K151 测量。
- MCU 路线不假设能跑浏览器 DOM／SVG 引擎。保留同一语义／配置契约，将眼形绘制改为本地栅格／矢量图元，独立评估刷新率、内存、SPI 带宽和中文字库。
- 降级顺序：关辉光与符号 → 降低微动作频率 → 简化形变 → 静态关键眼形＋状态文字。保留倾听／等待／故障区分；语音优先于装饰流畅度。
- 后台窗口暂停动画，恢复时使用**最新业务快照**；动画暂停不暂停会话时钟。正式实体显示进程重启后同样拉取最新状态，不重放历史表情。
- 提供本地 `motionIntensity`、情绪特效开关、字幕字号、亮度、动画减弱／关闭配置，无需新增产品配置网页。默认采用活泼设计与启用特效；减弱选项供用户主动选择。
- 减弱动画时以 0 ms 直接显示静态目标，关闭跳动／快速缩放／扫视／符号弹出；黑屏和插话切换仍立即生效。避免大面积闪光或红白交替警报。
- 几何、状态配置本地保存；断网不影响基础脸面。日志只记录状态、事件所属轮次、丢弃原因、耗时和性能，不为表情新增录音或摄像头采集。

## 11. 范围、证据与未完成事项

本轮整改覆盖设计规范与独立视觉预览，目标是直接解决眼形／模式相似、长条眼占主导、活跃度不足及特效受限四项体验问题。预览中的说话节奏、搜索、断网、插话与动作说明均为**模拟**。真实语音同步、模型情绪判断、硬件帧率、背光控制、2 英寸文字可读性和机械动作仍未验证。

v0.2 在原基本状态上增加兴奋、大笑、喜欢、好奇、自豪、坚定六种表达；增加各状态眼形缩略图、四模式同状态对照和满屏演出重播。单个情绪选择后可保持展示，便于观察；短时强演出结束后保留其核心眼形。生产四层合成、真实音频时序和完整业务取消契约仍属于 D2。

V1 视觉方向现包括多家族眼形、多符号及强情绪满屏演出。连续情绪记忆、摄像头视线跟踪、触摸互动、音素同步及复杂编辑器仍不进入本轮。满屏演出属于本次已授权设计范围，不再列为延期项。

v0.2 造型已获用户认可。v0.3 的渐进效果可独立体验，D2 对应 Mac 真实事件接入。硬件路线可以继续独立阅读和决策，本次不要求采购。
