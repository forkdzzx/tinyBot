# 本地唤醒与会话流程实现记录

> 2026-10-26 范围变更：用户已同意将稳定本地唤醒及其余四条短句延期至 [V2](../prd/v2-iteration-memo.md)。V1 用按钮开始聊天，Hi Jarvis 仅可选实验；本文为历史测试／评估记录，不要求重复五短句测试，也不再执行其中的唤醒研发下一步。

**最新：真人唤醒短测未通过。以下合成语音和工程联调记录不能代替识别可用性。** 见 [漏检分析与改动](wake-review-2026-10-25.md)。

2026-10-25，P1 Mac 原型。真人对话继续使用此前确认的 Seeduplex v3 提示，未改模型、音色或对话提示基线。

## 已实现

- 五条短句继续统一读取 `prototypes/expression/state.mjs` 的 `WAKE_PHRASES`，由模型作者提供的发音词典转换为本地 KWS 音素词表；不是字符串模拟识别。
- `sherpa-onnx-node@2.0.0` 原生 CPU 推理在独立子进程运行，避免阻塞语音代理。子进程不继承云服务凭证；待机 PCM 仅通过本机 WebSocket 与 IPC 传递，不保存录音。
- 普通入口启用本地唤醒，检测成功后发放单次、15 秒有效的会话许可；语音代理在许可校验成功后才创建云会话。诊断入口需显式指定诊断模式。
- 结束会话关闭云连接，保留麦克风供本地唤醒；关闭交互或页面进入后台会关闭全部连接、音轨和 AudioContext。唤醒模型故障时明确报错，不能偷偷改为云端常驻识别。
- 浏览器只暂存检测成功之后的输入，最多 8 秒；连接成功后以最高两倍实时速率清空积压。检测成功前的待机声音不会补传云端。
- 静默两分钟以实际音频播放结束为起点；用户开始说话、生成、播报会使旧计时器失效。“等一下，我想想”等明确短句进入十分钟等待，继续说话恢复；“结束聊天／停止聊天”等短句结束会话。
- 命令由最终云端转写匹配一组明确表达，避免把引用、否定或讲解中的相同词误当命令。尚未覆盖任意语义改写；断网不支持离线识别这些命令。
- 服务端在思考等待时丢弃输出，客户端清空待播音频；等待恢复时解除音频屏蔽。打断后的旧音频完成事件也会被丢弃，防止它错误开启新一轮静默计时。
- 移除旧的整轮十分钟开发上限，改为前台页面心跳；45 秒无心跳关闭云端会话。十分钟仅表示延长等待期限。

## 模型与复现

模型是 `zh-en-3M-2025-12-20`，chunk 16、left context 64、INT8 encoder/joiner + FP32 decoder。来源为作者 pkufool 的 [ModelScope 仓库](https://modelscope.cn/models/pkufool/icefall-kws-zipformer-zh-en-3M-2025-12-20)，权重固定 revision `541d04e28be57efc6fdf46a341da09e043a37b52`。安装脚本逐个核对 SHA-256；地址与哈希位于 `prototypes/voice/wake-model.mjs`。权重与词表约 5.2 MiB，发音词典约 16.4 MiB；不包括原生运行库占用。

[官方 KWS 文档](https://k2-fsa.github.io/sherpa/onnx/kws/pretrained_models/index.html)说明自定义短句以音素与标签配置。[Node API 文档](https://k2-fsa.github.io/sherpa/onnx/javascript-api/index.html)提供原生 Node 接口。当前配置为 2 个 CPU 线程、keywordsScore 1、threshold 0.25、trailing blanks 8；这些是初始工程参数，尚未经真人调优。

模型作者已在 [上游讨论](https://github.com/k2-fsa/sherpa-onnx/issues/3802)说明更新 ModelScope 许可证；本地保存的作者 README revision `afc4a534ef85f2db4f84f05ed78eaac385b3387e` 声明 Apache License 2.0。框架和原生 npm 包亦声明 Apache-2.0。模型保存在忽略目录 `runtime/models/`，未打包发布。

```sh
npm ci --ignore-scripts --registry=https://registry.npmjs.org
npm run voice:wake:setup
npm test
npm run voice
```

当前 Mac 无需重复安装。GitHub 大文件下载本次不稳定，已使用作者的国内源；初始不完整下载文件已清理。原生推理子进程自动设置对应平台库目录；启动失败时先检查本机架构的 `sherpa-onnx-*` 包是否实际安装。模型未准备完成时不会自动联网下载或打开云端录音。

额外验证命令（会调用已开通的云语音服务并产生用量；均不使用真人麦克风、不保存 PCM）：

```sh
npm run voice:wake:smoke
node prototypes/voice/wake-integration.mjs
```

## 本轮证据

| 检查 | 结果与边界 |
| --- | --- |
| 自动化单元测试 | 30/30，通过计时、取消失效、会话许可与原有语音回归；不测主观听感 |
| 五条合成唤醒短句 | 每条一次，5/5 匹配各自完整标签；长短句未混记为同一成功 |
| 五条普通合成语句 | 0/5 误触发，含中英文及 service/jellyfish 近音；样本很小 |
| 原生处理 | 每条输入含尾部两秒静音，处理与 IPC 总耗时约 51–93 ms；这是加速离线处理耗时，不是端到端唤醒延迟 |
| 本机代理与真实云服务 | 非唤醒输入不建云会话；无许可拒绝；Hi Jarvis 后建会话；思考等待抑制输出、继续说话恢复、结束关闭、再次唤醒通过。全程仅建一个被许可的测试云会话 |
| 浏览器加速时钟 + 模拟云事件 | 等待恢复后能排程音频；按播完计时；十分钟超时回待机；关闭后音轨 ended。不是十分钟真实运行验证，脚本 `output/playwright/client-lifecycle-check.js` |
| 用户内置浏览器 + 真实云端问候 | 不启用麦克风，完整排程播放后显示“问候测试完成 · 麦克风未开启”，收到 local.closed；未代替主观听感验收 |
| 真实浏览器 + 静音测试输入 | 页面进入真正的本地待机，收到原生识别子进程 ready/listening；未使用真人麦克风 |

浏览器自动化最初出现两次测试自身问题：关闭事件监听注册过晚、加速时钟贴近边界时多走了几毫秒；已修复测试并重跑通过，未把失败运行记为通过。

原始结构化报告：`runtime/wake-smoke.json`、`runtime/wake-integration.json`。浏览器测试使用模拟输入／时钟的部分会单独注明，不能当成十分钟实时时长验证。

## 待验证与下一步

先按 [真人短测](local-wake-test.md)验证实际发音。特别观察单独 Jarvis 与长句的前缀冲突、停顿、误唤醒、等待后能否恢复声音。待机只识别关键词，不判断是谁、是否在对它讲话；谈论 Jarvis 的普通句子也可能唤醒。

唤醒词后无停顿立即接问题可能在检测完成前已说出部分问题；当前不补传这段待机声音，存在丢首词风险，尚未宣称通过。云端连接耗时也计入首次使用体验。之后再补真实十分钟等待、长时间运行、外放回声及正式唤醒次数统计。

本实现只验证当前 Mac，不能据此认定 ESP32 的 K151 成品单机能运行这套 Node 原生模型。A1/A2/B 路线、主控采购与硬件成本决策仍保留待后续评估。
