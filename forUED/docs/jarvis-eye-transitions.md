# Jarvis 眼神渐进切换规范 v0.3

适用于沿用 v0.2 造型的屏幕实现。用户已认可这组眼神，希望切换时有类似 iOS 和 macOS 的连续感。交互人员用本文选切换时机，渲染器用本文及配套代码复现中间帧。24 张脸的含义、实际轮廓与四种模式的身份沿用[眼神设计方案](jarvis-eye-interaction-design.md)。

例如 Jarvis 正在听你说话，你说完后它开始思考。字幕区先反映输入已结束，两只眼睛在原来的位置渐渐转成一只豆眼和一只思索环。当你半路补充一句时，它可以立即转回来。眼睛、字幕和声音分别在各自应当变化的时刻响应。

Apple 的动效指南强调反馈应当简短、可取消，并应为偏好减弱动态效果的人提供替代呈现。WWDC 的流畅界面设计讨论了如何在运动中改变目标。本规范借鉴这两点。下文时长、曲线和轮廓处理是 Jarvis 对小屏双眼的设计取值。[Apple Human Interface Guidelines · Motion](https://developer.apple.com/design/human-interface-guidelines/motion/) · [WWDC18 · Designing Fluid Interfaces](https://developer.apple.com/videos/play/wwdc2018/803/)

## 谁决定下一张脸

渲染器的输入是一份已经生效的显示目标。正式集成时，先由会话层裁决事实，再向渲染器发一次更新。相同事实的重复通知合并处理。用一个单调时钟取样眼形、动作、过渡和符号，让左右眼在一帧中绘制。

| 输入 | 由谁决定 | 合成方式 |
| --- | --- | --- |
| 运行状态 | 电源、会话、录放音、搜索任务的本地事件 | 决定是否点亮、当前状态标记与字幕来源。倾听和说话均以实际输入或播放事件为准 |
| 情绪 | 当前有效回复片段的表达意图 | 可临时把主眼形改成心、星、泪滴等。字幕继续跟随当前片段。意图到期时重新计算此刻的运行状态和模式 |
| 模式 | 四模式调度器提交的生效模式，包括回滚 | 在待机、倾听、说话中决定轮廓与节奏。在喜欢、兴奋等共享主眼形中决定配色、局部特征和模式符号 |
| 勿扰、关节可用性、效果配置 | 本地开关和设备状态 | 独立更新标记或效果。勿扰中的主动提问仍进入倾听。单轴故障只停对应动作，语音和字幕继续 |

预览目录把运行状态与情绪都展示成可选的脸面。正式接入时需要同时保存业务状态和当前情绪。例如 `speaking + love + english` 显示喜欢的心眼、英语模式特征与正在播放的英文字幕。稍后若音频先结束，倾听接管，旧片段结束回调到达时丢弃。勿扰与故障均可与该流程并存。事件归属和失效规则见[表达事件契约](jarvis-eye-interaction-design.md#72-最小表达事件契约设计尚未接入)。

## 每次切换选哪一种动效

由上往下采用第一条适用规则。“进入”指状态 ID 真的发生了变化。只换字幕维持当前过渡；主动重播重置该情绪的演出年龄。表中时间为正常播放时长，预览的慢看倍率只影响观察。

| 触发与示例 | 策略 | 正常时长 | 屏幕应呈现什么 |
| --- | --- | ---: | --- |
| 目标为 `off`，包括过渡途中按关机键 | `blackout` | 0 ms | 立即清空所有层和文字 |
| 语音链路明确报告插话 | `interrupt` | 0 ms | 直接显示可倾听的眼神，清旧回答字幕与特效，即便目标已是倾听也能取消未完成的过渡 |
| 已启用减弱动画，或暂停后主动选另一张脸 | `instant` | 0 ms | 直接绘制可辨的定格造型 |
| 进入 `offline`／`fault` 样张 | `device` | 0 ms | 状态文字立即明确。正式设备中的单轴故障按前述属性处理 |
| 已启用后从全黑点亮至可交互状态 | `wake` | 260 ms | 眼形在本来的位置显现，字幕按实际就绪状态更新 |
| 进入 `waiting`／`dnd` 样张 | `quiet` | 180 ms | 收掉热闹符号，眼睛沉到小圆珠或月牙。只切勿扰开关时更新属性 |
| 正常播放结束转 `listening`，或用户从安静等待继续说话 | `focus` | 160 ms | 第一帧即给出倾听状态，双眼快速聚焦，末段轻轻收住 |
| 模式改变，含未命中上方规则的“换模式＋换眼神” | `mode` | 400 ms | 当前位置接到新模式眼形和配色。保持倾听而换到英语，也用这条 |
| 任一端是情绪，例如思考→疑惑、共情→鼓励、喜欢→待机 | `emotion` | 320 ms | 在两个造型间收放，保留弧、环、心、星等完整轮廓；符号随其所属情绪进出 |
| 其余状态变更，例如倾听→思考、思考→说话、待机→困倦 | `state` | 240 ms | 眼睛连续变到下一姿态，搜索框、缺口环、闭眼弧保持可识别 |
| 运行状态、展示眼神和模式均相同 | 保持 | 沿用当前进度 | 重复事实不重新启动动画。明确插话、关屏和取消仍优先执行 |

表中“情绪”包括 `happy`、`excited`、`laughing`、`love`、`encouraging`、`curious`、`puzzled`、`surprised`、`empathetic`、`teasing`、`proud`、`determined`。困倦样张的实际 ID 为 `sleepy`。进入黑屏目标统一用 `off`。业务侧的“未启用”“正在关机”等语义由适配器映射为已交付目标。原方案中的主动邀请、迟疑等设计意图可在后续单独制样。

### 画出中间帧

把本次经过毫秒数除以表中时长并夹在 0 到 1，记为 `u`。0 ms 策略在接收该事件的更新中直接采用目标。其余情况用下列函数求目标权重 `w`，旧画面的权重为 `1 − w`。

| 过渡 | w | 手感 |
| --- | --- | --- |
| 聚焦 `focus` | `1 − (1 − u)³` | 前段先跟上输入，末端减速 |
| 模式 `mode` | `6u⁵ − 15u⁴ + 10u³` | 开头和结尾舒缓，中段清楚可见 |
| 其他渐进 | `3u² − 2u³` | 双端缓动，适合相邻的会话步骤和情绪 |

逐眼保留正在显示的中心位置、旋转角与缩放。中心及缩放按权重趋向**此刻目标动作**的位置与尺度；旋转取短弧，避免接近正负 180° 时转上一圈。让旧轮廓和新轮廓围绕这只眼共同的锚点按权重显隐。心形带尖、圆环有孔，一对几何命令可以完全不同，端侧按轮廓叠化即可实现。状态标记和字幕独立更新，声音开始、停止均不用等待几何就位。

**可移植的中途改向样例。** 从日常待机切工作待机，200 ms 时模式曲线正好进行到一半，此刻日常和工作轮廓的权重各为 0.5。如果改选英语待机，新过渡从这张混合帧出发。在新一段的 200 ms 时，三种轮廓的权重分别为日常 0.25、工作 0.25、英语 0.50。在新一段 400 ms 到达时只保留英语。一个只保存“上一个枚举值”的驱动会在第二次点击时跳回纯日常或纯工作，按这组权重即可检出。校验颜色时应考虑具体图层的 alpha 合成方式，数值权重并非对截图亮度的强制比例。

**三个不同的时钟。** 会话超时由业务计时；一次切换取上表的毫秒数；满屏庆祝从所属事件首次进入计算 3.6 秒。模式切换只替换展示目标，不能顺手重启庆祝。在任何时刻离开兴奋语境，应当先清空旧满屏层，即使星眼还在向下一个造型叠化。惊讶本身的睁大、短暂停住，和它从前一张脸接过来的形状叠化也可重叠进行。

### 接到自己的显示循环

下列 Node 例子在仓库根目录以 ES 模块执行。浏览器也可先用普通 script 标签加载同一文件，然后访问相同的全局对象。无须连接网络。[过渡采样器源码](../design/eyes/transitions.js)

```js
import './design/eyes/transitions.js';

const {createTransition} = globalThis.JarvisEyeTransitions;
const face = createTransition({state: 'idle', mode: 'daily'}, 0);
face.setTarget({state: 'idle', mode: 'work'}, 0);
const frame = face.sample(200);
console.log(frame.layers.map(({mode, weight}) => [mode, weight]));
// [ ['daily', 0.5], ['work', 0.5] ]

// 在中途收到插话。调用前由会话层取消旧播放、字幕和粒子。
const listening = face.setTarget(
  {state: 'listening', mode: 'work'}, 210, {interrupt: true}
);
console.log(listening.kind, listening.settled); // interrupt true
```

每个眼神目标必须包含一个有效的 `state` 和一个有效的 `mode`。未知值会触发 `RangeError`，集成层应在调用前校验。传给 `setTarget` 和 `sample` 的时间单位均为毫秒，来自同一个单调时钟。每一显示周期用 `frame.layers` 取得轮廓组合与权重，用已经裁决的 `frame.target` 更新业务状态标记。对每只眼的连续位置、旋转与缩放，可复用 `blendPose(from, to, easedProgress, targetAtStart)`，姿态字段为 `x, y, rot, sx, sy`，角度单位为度。在收到另一个目标的同一时刻锁定可见姿态作为新的 `from`。C++ 显示驱动可按前述分类表、缓动公式和 200 ms 取样案例实现同一协议。

## 同时到达和反向切换

1. **同一帧变更多个字段。** 例如正在思考的日常 Jarvis 切到工作模式恰逢播放开始，先合成“工作＋说话”的目标，再从屏上当前的样子向它切换。中途不经过“工作待机”。字幕从播放开始更新。
2. **目标在运动中变化。** 正在切日常→工作时，用户说“不要切换”。先取此时屏幕上的过渡进度和可见眼形，再走到日常。连续点三种模式也使用最新目标，整个过程中不排队回放旧目标。
3. **模式变化时仍处在同一情绪。** 兴奋时进入陪伴模式，星眼可以保持，新的模式装饰逐渐显现。仅换模式不会给同一过关事件追加一次 3.6 秒庆祝。若业务同时确认本轮失效，先清除旧演出。
4. **重复事件。** 重复的状态通知、同一事件的分片更新、只换字幕的 ASR partial，均保持已开始的眼神时序。用户在预览中主动按“重播演出”可重新观看一次开场。
5. **插话、会话结束与迟到事件。** 会话层先使原 session／turn／response 失效并停止旧音频、字幕和演出，接着显示当前真实目标。取消后的旧搜索结果、情绪或播放回调不能还原旧眼神。会话结束通常到当前模式待机，用户继续说话则到倾听。
6. **电源与异常。** 收到关屏要求即呈全黑，清除字幕、旧形状、模式标记和粒子。恢复显示时以当前运行事实为起点。阻塞性连接错误立即呈现文字；某个关节不可用时，先在驱动层取消该轴，再更新状态提示。

## 移植到机器人屏

- 以屏幕上的左右眼中心为锚点，轮廓按相同纵横比缩放。在 720×720 和横向 320×240 上分别布局字幕与眼区。颜色、图形、局部动作一起参与表达。字幕绘在最高层排成一至两行，保留独立底色和静止基线。
- 能画矢量的设备可以直接使用眼形路径。采用位图的设备可栅格化各模式的脸面，在同一眼区内混合当前与目标；存在环孔的眼形需要保留透明区域。切换中再次收到目标时，可以保留一份此刻的眼区合成结果作起点，清理临时图层。在单片机上按眼区分块复用缓冲，避免常驻所有脸面的整屏位图。
- 用毫秒计时，按显示器下次可刷新的时刻直接取正确进度。暂停供审阅者冻结视觉；正式设备挂起后恢复时重新读取电源、轮次和播放状态，直接对齐当前目标。恢复联网不触发旧回复的眼神和庆祝。
- 在低性能设备上先保留轮廓、即时状态和可读字幕，再按实测资源预算增加阴影、符号与粒子。关掉特效时仍应能辨认眼形。减弱动画与静态显示均保留文本状态。硬件上的选项可映射到本地配置。
- 屏幕切换本身不产生电机指令。若同一个业务事件还需要点头，由动作控制器接收带轮次的独立命令，按该关节的速度、幅度与限位执行。插话时撤销未启动命令，已在动的关节按控制器策略平稳停下。

## 验收时实际看什么

| 操作 | 合格表现 | 验证环境 |
| --- | --- | --- |
| 倾听→思考→说话→倾听，再看待机→困倦 | 双眼留在同一脸面上，形态渐变，全程没有意外闪黑。字幕先显示当前事实 | 独立预览；真实播放驱动归 AC-21 |
| 在日常、工作、英语间连续切换，在第一段过渡中再次点选 | 从可见中间帧接续，最终只有英语的几何与模式标记，指示与最终选择一致 | 独立预览 |
| 共情→鼓励，开心→兴奋，兴奋期间换模式，再主动重播 | 泪滴、单眨、笑弧和星眼各自可辨。单纯换模式保持同次演出的年龄；主动重播重新开始 | 独立预览 |
| 正在庆祝时改为安静等待、模拟插话或黑屏 | 旧庆祝粒子和字幕清除。插话显示正在听，黑屏清空全部图层 | 独立预览；真实音频及两轴取消归 AC-22 |
| 重复发送同态更新，打开减弱动画，再切换屏幕比例 | 同态更新不重播。静态也可认出目标，文字不随脸部弹动，两种比例均可读 | 独立预览；实物在 20／35／50 cm 复验 |
| 实机注入“插话→迟到旧播放结束→新问题”；在云端延迟时计时 | 新输入首次可见反馈目标 ≤300 ms，单独记录首帧和过渡完成时间。迟到事件无画面／音频／电机残留 | Mac 业务接入和目标硬件阶段，关联 AC-22／23 |

日期为 2026-11-08。真实声音与机械同步、实际帧率、缓冲占用、实屏字幕可读性和用户对新过渡的体验仍需各自验收。
