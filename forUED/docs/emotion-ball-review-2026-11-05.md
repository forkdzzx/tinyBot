# emotion-ball 源码审阅与 Jarvis 设计借鉴

审阅日期：2026-11-05。范围：为 Jarvis 的眼神交互设计提供依据，不代表已接入该引擎或已通过机器人硬件验证。

**阅读更新：** 本文源码事实与固定版本保持有效。第 4、5 节是 v0.1 时的初始取舍；用户体验后已撤回视觉“克制”和少量符号限制。当前以 [v0.2 交互方案](jarvis-eye-interaction-design.md)为准，加入多样几何、四模式特色、丰富符号与兴奋满屏演出。下文“去掉彩带”“克制唤醒”等旧取舍不再作为当前约束；不直接复制第三方源码／坐标的处理方式不变。

## 1. 审阅版本与结论

- 仓库：[Aithena/emotion-ball](https://github.com/Aithena/emotion-ball)。
- 固定版本：[e09d114d40888e24afc394098cd3f09b0a258d8c](https://github.com/Aithena/emotion-ball/tree/e09d114d40888e24afc394098cd3f09b0a258d8c)，提交时间 2026-08-20 16:48:32 UTC。
- 检查对象：`rings.js`、`emotions.js`、`engine.js`、`ball.js`、README、商业许可、许可说明及该版本完整 Git 文件树。
- 审阅快照位于 `/private/tmp/jarvis-emotion-reference`，是临时研究材料；本报告的固定版本链接是长期可复核入口。

最值得 Jarvis 借鉴的是它把**眼形、表情编排、动画驱动、绘制**分开，以及从一个姿态连续过渡到下一个姿态的方式。Jarvis 应采用这一设计思路，重新绘制符合伊娃气质的双眼，并在其前面增加由真实会话事件控制的状态裁决层。整颗球的外形、彩带、粒子和自旋不是这次设计的核心。

## 2. 源码如何工作

| 层次 | 已核对的实现 | 对 Jarvis 的价值 |
| --- | --- | --- |
| 几何数据 | 25 对左右眼，每只眼 48 个轮廓点；另有三类身体轮廓。眼形不是位图帧。 | 同样数量、顺序一致的轮廓点能支持连续形变；Jarvis 自行绘制眼形，不复用原项目坐标。 |
| 表情数据 | 32 个配置：生命周期 8 个、情绪 12 个、工作状态 12 个。每个配置组合眼形候选池、眨眼、开合、姿态、循环动画、进入序列。 | 一种情绪可有少量相近姿态，避免始终停在一张脸上；候选池必须保持相同语义。 |
| 驱动层 | 从当前轮廓继续插值；姿态过渡使用缓动；眼形与开合使用阻尼弹簧，并将积分拆为不大于 1/120 秒的子步。 | 切换不中断连续性，避免贴图跳变；动画在本地运行。 |
| 序列层 | 进入演出结束后可回基础姿态、保持末帧，或切到下一状态。 | 为“惊讶一下然后继续听”“温和确认后继续说”提供可配置语法。 |
| 绘制层 | SVG 路径更新与属性缓存；按身体轮廓做眼睛投影，转到背面时隐藏；可关闭粒子等效果。 | 借鉴静止时减少重建与缩小特效开销；平面屏幕上的双眼不需要球面投影。 |
| 宿主接口 | 提交表情 ID、目光位置、活动开关等；提供变化、提示、错误回调。 | 保留有限、可校验的表达接口，但由 Jarvis 业务状态决定是否接受。 |

证据：[几何数据][rings]、[表情定义][emotions]、[弹簧与姿态插值][spring]、[逐帧合成与序列收尾][compose]、[渲染与投影][render]。

六种动画原语是正弦摆动、平滑左右张望、脉冲、伪噪声抖动、三角波扫视、周期眨眼。它们组合出节奏，而不是每个表情各写一套运行代码。原项目同时叠加常驻微漂移；Jarvis 需要减弱幅度并保证双眼协调，避免持续游移显得没有认真听。[动画原语][primitives]、[微漂移与姿态合成][compose]

## 3. README 与代码的边界、需要补齐的地方

以下是静态源码检查结果；涉及潜在失败的条目尚未通过运行原项目复现。

| 项目 | 源码证据与判断 | Jarvis 的处理 |
| --- | --- | --- |
| “说话”不是音频同步 | `39` 使用固定 680 ms 的缩放/位移周期；没有输入音频能量或播放游标。 | 只在本地实际播放开始后显示说话；若加入眼神韵律，应跟播放包络或句段边界。 |
| 单一表情 ID 不等于会话状态机 | `handleAIMessage` 直接调用 `setEmotion`，没有会话 ID、轮次 ID、消息时效或优先级。 | 独立区分运行状态与表达语气；丢弃过期轮次，插话与关机可抢占。 |
| 重复状态会重新编排 | 再次 `setEmotion` 会重置序列起点、轮换时间和动作调度，不因 ID 相同而整体忽略。 | 相同状态更新应合并；确需再次演出时使用明确的重播事件。 |
| 动作取消并不完整 | `spin` 进行中拒绝新请求；切换表情没有统一清除旋转、弹跳及眨眼队列。 | 所有短演出归属于当前轮次，可取消；退出时从当前位置平滑收尾，不让旧情绪残留。 |
| 自动休眠只是通用计时 | 默认 60 秒待机、180 秒睡眠；主要依据最近的状态操作，不了解用户正在讲话、等待思考或搜索。 | 由 Jarvis 已有生命周期负责计时；关闭渲染引擎独立的会话/休眠判断。 |
| “最多 3 条动画”是约定 | 校验动画类型，但没有限制动画数量。 | Jarvis 配置明确层数与幅度上限，避免多层叠加失控。 |
| “50+ 自定义”是约定 | 校验 ID 为非空字符串，没有强制编号区间，也允许覆盖已有注册项。 | Jarvis 使用自身稳定的语义 ID 与配置版本，不依赖此编号体系。 |
| “完整校验”范围有限 | 未完整验证数值有限性、范围、池类型、序列非空等；空 `frames` 可通过验证，而序列采样会读取末帧。 | 加入类型、范围、非空、时间单调性检查；导入失败保持上一份有效配置。 |
| “永不白屏”有前提 | 常见协议错误会回退；未知 ID 在回退成功后仍返回 `true`，回退配置不存在则失败。不能扩展解释成所有坏配置均安全。 | 未知情绪仅退回中性语气，仍保留真实“离线/倾听”等状态；独立兜底绘制两只中性眼睛。 |
| 共享 rAF 不代表免费增加实例 | 使用一个 rAF 调度，但内部遍历实例，各自合成姿态和更新 SVG。 | 动态主脸保持一个实例；表情目录优先静态缩略图，预览时再播放。 |

证据：[回复配置][reply]、[状态切换与协议处理][switch]、[自旋与眨眼][actions]、[配置验证/注册][validation]、[共享时钟与默认休眠][ticker]、[序列采样][sequence]。这些差异说明它适合作为视觉设计参考，不能代替 Jarvis 的交互调度。

## 4. 32 个原状态在 Jarvis 中如何取舍

下面是设计映射建议，不是已实现清单。原编号仅用于核对，不要求 Jarvis 沿用。多个原状态可以复用同一套 Jarvis 眼形；业务含义由状态文字和上下文区分。

| 原 ID / 名称 | Jarvis 建议 |
| --- | --- |
| 00 睡眠 | 借鉴慢闭眼，用于困倦待机；与真正断电黑屏区分。 |
| 01 唤醒 | 简化成短睁眼反馈，不阻塞立即开始倾听。 |
| 02 待机放空 | 保留低频眨眼和微动，去掉周期性自旋/弹跳。 |
| 03 好奇 | 用作追问、邀请展开话题的轻度语气。 |
| 04 发呆 | 不独立立项；并入待机变化，避免双眼各看各的。 |
| 05 加载苏醒 | 仅在允许亮屏的初始化阶段提示；不覆盖 PRD 首次通电未激活黑屏流程。 |
| 06 休眠 | 并入困倦/低活动；勿扰另有明确状态标记。 |
| 07 抖动唤醒 | 不采用全脸抖动，用同一套克制的唤醒过渡。 |
| 10 开心 | 笑弧、轻抬眼，适合轻松对话和成功鼓励。 |
| 11 疑惑 | 小幅不对称；用于没听清或需要澄清，不责怪用户。 |
| 12 失落 | 改为温和关切；陪伴用户低落时出现，不因用户不回复而表演委屈。 |
| 13 惊讶 | 短暂睁大然后回落，保持可中断。 |
| 14 害羞 | 留作后续素材；不纳入当前 V1 默认人格，也不用整脸泛粉。 |
| 15 疲惫 | 仅作困倦待机变体，不在工作问答中表现不耐烦。 |
| 16 专注 | 小幅收眼与稳定正视；避免直接使用怒目池。 |
| 17 慌张 | 不作为正常响应；故障时优先清晰提示，不持续颤动。 |
| 18 无奈 | 改成短暂轻吐槽；工作受挫场景禁用。 |
| 19 满意 | 并入认可/鼓励，不持续重复点头。 |
| 20 困惑 | 与疑惑合并，V1 不要求区分两种接近语义。 |
| 21 生气 | 可保留为后续戏剧性表达素材；不因不同意见或操作失败对用户怒目。 |
| 30 思考中 | 上视或轻收眼；去掉头顶彩带，依真实等待事件进入。 |
| 31 接收任务 | 短眨眼确认，表示收到输入，不代表已理解正确或操作成功。 |
| 32 处理中忙碌 | 与思考共用基础眼形；文字解释具体等待原因。 |
| 33 任务完成 | 短确认/笑眼；保存成功须来自写入结果，不能随模型承诺提前触发。 |
| 34 出错 | 稳定的疑惑/中性眼形与短状态文字；不用红白急闪。 |
| 35 等待输入 | 保留倾听感；正视、少动，不必持续上下扫读。 |
| 36 联网加载 | 并入连接中状态；不让左右交替眨眼看起来像玩笑。 |
| 37 复述回忆 | 可作短思索变体，但复述时仍以真实播放状态为准。 |
| 38 拒绝/受限 | 温和说明与一次轻摇头；不将“无法确认”表达成不耐烦。 |
| 39 输出回复 | 重新设计为实际播放驱动的说话态，不沿用固定节拍代替同步。 |
| 40 检索资料 | 短扫视 + 搜索状态文字；取消搜索后立即退出，不能持续忙碌。 |
| 41 停止终止 | 区分结束会话回待机、插话转倾听、系统关机收眼变黑三种路径。 |

原始状态的权威定义见 [emotions.js][emotions]；本表是根据 Jarvis PRD、人格和硬件条件做的设计推导。

## 5. 适配“黑屏上的双眼”，不是搬入一个球

1. **重新绘制眼形。** 保留伊娃式简洁发光双眼和留白，眼睛可用开合、眼睑斜率、弧度、宽高、不对称和视线表达情绪。不加入球形身体、嘴巴或鼠标跟随作为机器人默认行为。
2. **把不同问题分开表达。** “倾听/思考/说话”说明交互阶段，“温暖/好奇/惊讶/吐槽”说明语气；两者可组合。不能让一个“开心” ID 覆盖掉正在倾听的反馈。
3. **从语句与事件安排表演。** 同一句“没问题”可能表示接收到问题，也可能表示完成保存；只有业务结果才能驱动成功反馈。眼睛表达 Jarvis 的交流姿态，不宣称识别到了用户的真实情绪。
4. **收敛不确定的表达。** 没有明确情绪信号时保持中性、专注。模型可以建议白名单内的语气，不能自由发送眼坐标、电机角度、无限时长或控制系统状态。
5. **保留轻微变化，限制随机性。** 同一情绪可以有 2–3 个接近的眼形，眨眼间隔可略随机；重要反馈、错误与关机不随机。倾听时不反复左右巡视；没有摄像头时也不暗示正在跟踪用户。
6. **眼神先行，肢体补充。** 视觉反馈不等待电机；点头/摇头是低频有限动作，故障时保留眼神。原项目的整圈自旋不能直接映射到 Jarvis 的底座关节。
7. **适配两种候选屏幕。** 用归一化坐标保留双眼与下方字幕安全区；方屏与 320×240 横屏分别编排，而非把整脸等比缩小后让字幕无法阅读。屏幕与硬件路线尚未确认，本审阅不做采购结论。
