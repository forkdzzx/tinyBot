# 固定语音诊断集 v1

`baseline.json` 固定模型、提示及音色，`cases.json` 固定案例与人工判定标准。此基线包含既有失败后的提示修改，不能作为完全未见过的测试集。

```sh
npm run voice:eval
```

调用已开通 Seeduplex：13 条问题先生成合成语音，内存缓存，每例三个独立会话，最多两个会话并发。每次执行会产生云用量；不自动周期执行。新一轮合成的 PCM 可能变化，报告保留音频内容 SHA-256 与模型/提示标识以识别这种差异，但不保存音频。采集仅用于诊断，没有麦克风、重叠插话或实际播放。

报告保留每轮转写、回答、服务端历史、usage、时间戳与 log ID。`unreviewed` 不能当作通过；必须人工对照 criteria，区分主要目标、其他质量缺陷和基础设施错误。原始报告不可为提高通过率而改写。后续新提示应另建基线目录，不覆盖本轮。

文本模型对照先按 [开通说明](../../docs/ark-evaluation-setup.md) 配置，再运行：

```sh
npm run voice:eval:ark -- --source runtime/evals/1792853530188-voice-v1-20261024.json
```

它复用音频基线实际转写，逐例重新构建独立本地历史并发送给文本模型；共 42 次调用，接口错误即停。双方系统提示相同，输入转写相同，但模型模态和历史实现不同；后续回合各自沿用自己的回答，因此比较复述正确性时须参考各自上一答。没有独立 ASR/TTS，不可将文本完整回答耗时当作完整语音首音延迟。

本轮复核与未解决问题：[评估报告](../../docs/voice-evaluation-2026-10-24.md)。

2026-10-25 已完成方舟真实对照：[结果与边界](../../docs/voice-comparison-2026-10-25.md)。重复执行会重新产生云用量，不为查看报告而重跑。

## 下一轮：流式时序与新增案例

已完成的本轮证据与复核见 [流式与新增案例报告](../../docs/voice-streaming-review-2026-10-25.md)。

```sh
npm run voice:eval:next
```

保持 `baseline.json` 的提示与模型设置，新增案例固定在 `next-cases.json`，报告记录该文件 SHA-256。6 类场景各 2 个新会话，合计每条路线 28 轮。先获取 Seeduplex 的真实转写，再交给方舟流式调用；双方各自保持自己的回答历史。生成的 14 条输入语音仅在内存复用，不落盘。这是未在提示中逐字列举的新案例，不是完全独立盲测，也不测真人声学效果。

另有 3 个固定问题各重复 2 次，同时比较流式与非流式，共 12 个方舟请求；每次独立会话，第 2 次反转两种模式顺序。同一轮报告中比较，避免只用不同日期的测量解释模式差异；模型输出长度、网络与服务端状态仍可能不同。

流式指标从请求发出开始：首个非空白回答文本片段、首个句末标点边界、完整流结束。不将角色字段或 usage 当成首 token；句末标点采用简单规则，不处理所有英文缩写、小数或代码语法，也不判断语义是否完整。无标点时首句字段保留 null；这些数值不等于语音首音或 TTS 已可用。

SSE 按官方 `stream: true` 和 `stream_options.include_usage: true` 请求，要求正常 stop 与 `[DONE]`，UTF-8 跨包增量解码。超时、截断、非法事件不得写入会话历史。[方舟 Chat API](https://docs.volcengine.com/docs/ark/chat-api?lang=zh&redirect=1)

单次方舟请求限 30 秒、512 输出 token，流式响应最多 1 MiB。出错停止派发新案例、保存已获得证据，不自动重试；已在途的另一对照会话允许结束。采集程序不自动根据关键词判定通过，须分别审阅识别偏差、主要意图和附加质量缺陷。
