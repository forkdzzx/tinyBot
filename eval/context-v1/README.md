# 记忆、模式与工具接口可行性实验

这是 P1 的 T-19 / T-34 独立实验，不会改变正在运行的网页或正式提示基线。`context-v1` 是实验编号，不是产品版本。

## 运行

在项目根目录运行：

```sh
node prototypes/evaluation/run-context.mjs
```

可传入 `context`、`isolation`、`tool` 或 `superseded` 只验证一组。另有 `update-id`（显式会话编号更新与新会话对照）和 `context-tool`（本地上下文工具三轮实验），用于复核已发现的问题及替代路径。读取已有 `runtime/volcengine.env`，**调用真实豆包服务并产生用量**。默认全套最多生成四条问题音频、建立四个测试对话；单个对话上限 120 秒，无自动重试。音频仅保存在内存，不使用麦克风、不播放、不保存录音。

## 固定案例与判定

问题与虚构资料在 [cases.json](cases.json)。不读取用户历史，不调用真实搜索，不把虚构资料写入用户记忆。

| 场景 | 核心判定 |
| --- | --- |
| 初始上下文 | 从设备注入资料回答项目代号、复查日及当前模式；问题本身不包含答案 |
| 同一会话更新 | 收到 `session.updated` 后引用新复查日和工作模式，再切换英语上下文；保持同一个会话 |
| 新会话隔离 | 不注入资料的新会话应说明不知道项目与日期，不能继承上一连接的测试事实 |
| 工具回传 | 服务实际返回函数名、参数和调用编号；按该编号回传本地模拟结果后，生成含正确时间的文字与音频 |
| 查询中换题 | 暂不回传工具结果，输入新问题；旧结果在本地失效，新问题仍得到回答，观察两秒静默窗口 |
| 本地上下文工具（单独运行） | 同一会话三次读取本地当前状态，先回答原资料，再用更新资料和工作模式，最后根据英语模式提出基础英文问题 |

每次结果以唯一文件名写入 `runtime/evals/*-context-tools-v1-20261026-*.json`，保存实际请求、问题、转写、最终回答、事件顺序、调用编号、音频字节数和供应商返回用量；不写凭证或 PCM。`protocol_completed` 只表示脚本收到预期协议事件，**不等于语义通过**；须人工审阅答案，并另写带证据的结论。

## 边界

- 资料通过受限上下文快照注入；没有实现检索、持久保存、自动提炼或冲突确认。更新测试里的纠正是预先确认的虚构数据。
- 模式只是实验提供的字段；没有实现自动切换、回滚、Skill 加载或完整英语教学。
- `lookup_fixture` 只返回固定本地模拟日程，不访问互联网；本实验不能证明实际搜索服务的权限、质量、费用或时延。
- `ToolTurnGate` 拒绝已登记查询在新轮次、关闭或重复完成后的结果。正式适配仍需处理迟到的函数调用事件、多个并发工具、断网、真实播报与收音，不把此实验当作完成 T-36。
- 测试串行等待回答；供应商可能返回无编号的 `response.done`，通过当前窗口内的文字完成事件关联，不能把这种简化直接用于多工具并发调度。
- 合成回环不能替代真人听感、麦克风声学、最终硬件或长期稳定性验收。

2026-10-26 人工审阅结论：直接更新虽然收到确认，但仍回答旧资料，不能作为通过；本地上下文工具路径获得最小成功证据。详见 [实测报告](../../docs/context-tools-review-2026-10-26.md)，不要只看脚本退出码。

协议依据：[豆包实时语音模型 3.0 官方接入文档](https://docs.volcengine.com/docs/DoubaoVoice/endtoend-realtime-voice-full-duplex-version?lang=en)。本实验以实际回包验证文档中的会话更新和自定义工具机制，不混用其他实时语音协议。
