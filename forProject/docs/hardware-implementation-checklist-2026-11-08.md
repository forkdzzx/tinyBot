## 我需要投入多少时间

工程总工时包括查资料、写代码、设备联调、常规返工和现场操作。**“其中你现场”已经包含在工程总量里**，覆盖必须由持有设备的人做的工作，如插电、刷写、录下异常时间、在书桌试听。你若自己承担开发，还要投入对应的编码与调试时间。人时、日历工期和云端运行费用分别计算。

| 路线 | 只选这一路线时的设备接入工作 | 工程人时 | 其中你现场 | 首个可能让方案停止的结果 |
| --- | --- | ---: | ---: | --- |
| 小木 C6 | 机内 Linux、音频播放与取消、脸屏、关节、按键 | 40–90 | 8–16 | 只能显示原厂表情，无法显示任意中文字幕 |
| K151 A2 | Linux 业务加终端语音桥，保留机身声音 | 70–150 | 10–22 | 边播边录出现自激，或终端无法及时清空旧音频 |
| 陆吾 RIG-Arm 整机 | ESP32 固件、音频桥、关节限位及圆屏 | 80–160 | 12–24 | 1.09 英寸屏无法满足实际距离的字幕阅读，或长期插电需改线 |
| K151 C1 成品会议麦 | USB 音频与设备控制，三台桌面设备联调 | 40–90 | 8–16 | 你不接受声音从桌旁会议麦发出，或两台主设备不能按要求关机再开 |
| K151 A1 单机 | 在 MCU 上适配会话、存储与联网协议 | 160–320 | 18–36 | 持久化、音频和显示并发时资源不足 |
| 或宇 WatcheRobot | 独立 Linux 宿主、RTC 媒体、设备适配 | 80–180 | 12–26 | 交付固件缺全双工 RTC，或 SDK 无法在最终宿主运行 |

**以小木为例。** 路线接入 40–90 小时，加公共软件 66–128 小时和正式验收／交付 25–42 小时，约 **131–260 工程小时**。其中本人现场合计 **22.5–41 小时**。如果你独立包揽开发，应按工程总投入规划。上限和下限都是在原厂接口可用、无需机内改造时的工程估算，等待物流、供应方答复与无人值守的运行窗口另排。整机适配试验已满足正式次数、配置与记录要求时，可直接复用证据。A1 等重写业务的平台应在实测原型后逐项扣除与共用软件重合的工作，再估全程。[已有公共工作拆解](bl-work-breakdown-2026-11-02.md)

## 所有可行路线共用的交付任务

下列工作只分配一次。每种型号另有专属任务，21 个变体是互斥选择，只有选中的工作进入实际排期。

- [ ] **选样前，你核实交付。** 确认确切 SKU、两轴已装好和已接线、恢复办法、国标电源、配套存储、到手价和交期。记录是否接受外置主机或外置声源。完整预算含运税、附件和余量，控制在 ¥5,000 以内。
- [ ] **到货后，你与开发者建立基线。** 记录版本、配件和原厂状态，测试两个关节、显示、收音、外放和按钮。保留恢复步骤。只接成品外部线，停用非必要视觉服务。先用 Mac 做开发和短测，最终交付须能脱离日用 Mac。
- [ ] **开发者迁移现有软件。** 语音入口是 `npm run voice`，复用现有豆包会话与取消逻辑，核目标设备能否提供输入、分块播放、清队列、按键与日志接口。`npm start` 可单独演示表情。把本地配置与凭证放在目标设备限定权限的文件内，记录安装、开机启动、停服和恢复步骤。[运行脚本](../../package.json) · [语音入口](../../prototypes/voice/server.mjs)
- [ ] **开发者补公共功能，你提供场景反馈。** 完成真实搜索、超时与旧结果隔离。主动邀请、30 秒无回应抑制和勿扰恢复。完善记忆检索与冲突、四模式回滚、英语中途中文求助、静默结束。验证重启后可找回历史、继续提炼，默认不保存录音。[记忆存储](../../prototypes/memory/store.mjs) · [模式控制](../../prototypes/modes/controller.mjs) · [项目工作状态](work-checklist.md)
- [ ] **开发者交付设备自检，你执行现场测试。** 准备不依赖云端的眼睛、双语字幕、两轴、声卡与按钮测试入口。动作失联后语音继续，重连后旧动作和旧音频都不重播。在 20 和 50 厘米处各读一行中文和英文，区分底板、身体及头部实际运动。
- [ ] **你与开发者记录正式验收。** 至少 10 轮连续对话。普通问题 20 次至少 18 次在 3 秒内开始有效回答。10 次插话至少 9 次在 1 秒内停止旧音，核新问题和旧表情／字幕／动作是否正确。至少 5 次完整按键电源循环、10 次按钮开始与结束会话、3 次断网恢复、8 小时混合运行。最终将结果对应至 PRD 全部 26 项，记录未通过项、失败条件和复测版本。[正式验收条件](../prd/prd-v1.1.md) · [台架计划](hardware-bench-plan.md)
- [ ] **开发者整理交付资料，你复现。** 实际 BOM 与云账单、设备镜像／固件版本、恢复说明、日志和备份入口、尚存限制与体验记录齐全。由你独立完成一次重启和历史恢复，给出愿不愿意继续日用的主观判断。[交付任务与时间口径](bl-work-breakdown-2026-11-02.md)

后续每条路线各自保留硬件、软件和退出条件。自建与缺货方案也列明如果重启该方案需要做什么。只估供货核查或静态演示的行，不能与整机交付时数横向比较。


## 预装身体与低装配方案

<a id="xiaomu"></a>

### C6 森灵小木编程版｜直接在机身运行 Jarvis

**现场要做的事**是接底座供电、配网、开通 SSH、看实体屏幕和试听。开发集中在机身内 Linux 和原厂驱动。小木官方示例能同时启动 16 kHz 单声道麦克风采集线程和分块写扬声器的线程，已经有逐轴运动示例。该音频示例在播完整个 WAV 后才结束，自绘字幕、回声处理和途中清队列的效果还要验证。[并行音频示例](https://github.com/TimuTechnology/senling-xiaomu-ros2-api-examples/blob/main/src/example/example/hardware_raw_demo.py) · [关节示例](https://github.com/TimuTechnology/senling-xiaomu-ros2-api-examples/blob/main/src/example/example/xiaomu_move.py) · [主控开放范围](https://github.com/TimuTechnology/senling-xiaomu-firmware)

- [ ] **硬件与交付｜你核型号，开发者列核验项。** 取得编程版到手价、供电底座和充电线的装箱单，确认可取得 SSH 与恢复方法。先核交付固件能否在保留眼睛时画任意中文短句，以及原助手退出后仍可调用驱动，记录接口、版本和演示结果。[编程版规格](https://www.timuai.com/order/code)
- [ ] **声音｜开发者适配，你插话试听。** 先停原助手，禁用示例中的摄像头线程，跑本地同时录放并记录是否独占声卡。将采集帧和豆包输出接入现有会话，给播放队列增加中止入口。你在 20 和 50 厘米自然插话，核对听到的停播时刻、旧声是否回来、机身是否把自己的声音当作新问题。
- [ ] **脸与动作｜开发者编写，你确认效果。** 在目标屏幕画一对眼睛及一至两行中英字幕，留存 50 厘米观察结果。分别发送 `HEAD_PITCH`、`HEAD_YAW` 和可用的身体轴指令，标定中位、方向、限位，记录转动时固定底板上方实际哪些部件在动。[原厂运动接口](https://github.com/TimuTechnology/senling-xiaomu-ros2-api-examples)
- [ ] **机内部署｜开发者负责。** 核 ARM 系统、可用空间和 Node 运行环境，在保留驱动的前提下替换原助手自启动，部署现有会话、记忆、Skill 与日志。实现机身服务退出、重启恢复，以及回退至出厂程序，交付可重装的部署步骤。
- [ ] **输入与电源｜你操作，开发者记录。** 核背键事件及独立聊天输入，实测插电冷启黑屏、按键启用、短按保存关机、同键再次启动。底座背键的原厂长按关机行为要在编程版实机复核。核原机摄像头默认禁用、未来独立计算节点的有线连接入口。

**决定下一步。** 先取得“同屏双语字幕＋独立控制双轴”的实物演示和“边播边听＋取消”的音频日志。若厂家只开放预设表情、原生电源必须拆机改造，或声流无法稳定接管，记录原机限制，暂停这条一体机路线。工程总投入初估 **40–90 小时，其中你现场约 8–16 小时**。拆分为接口与恢复 8–20、声音 12–30、脸和动作 10–20、部署及电源联调 10–20 小时。

### 陆吾 RIG-Arm 卡卡整机＋专用主机｜自己编写终端固件

**现场要做的事**是核实出厂已装配的型号、配网、软件校准五轴姿态和确认 1.09 英寸圆屏能否读清。`Hand-built Full Unit` 才是本路线比较的整机。原机采用 2S 7.4V 电池驱动舵机，公开固件能调用 yaw、pitch 等动作，语音监听方式受 AEC 编译和运行配置影响。[整机 SKU](https://shop.xgorobot.com/products/rig-arm-programmable-robotic-arm-steam-education-rig-series-universal-research-secondary-development-platform?variant=49162969514235) · [物料与供电](https://wiki.xgorobot.com/kb/pet-arm/d62767c63d18404182c870ba526bf879) · [语音状态机](https://github.com/LuwuDynamics/rig_omni/blob/c2b42cd73ef65f5cd2a158d6949f0273869454dc/main/application.cc#L881)

- [ ] **交付与机构｜你核实、上电。** 取得完整型号、国内交期和已含充电器资料。接原装供电，记录厂商允许的边充边用方式，按说明书完成初始姿态检查。先让其他关节保持安全姿态，只测点头、水平转动及回中，确认这种机械臂外形和转动轨迹符合你的期待。
- [ ] **终端固件｜开发者构建，你刷写。** 保存可回退的出厂固件和配置，编译对应 Arm 板型。接入动作指令，标定幅度、速度和失联停动逻辑，在 240×240 圆屏同时显示眼睛、中文和英语短句。你在 50 厘米处试读后再投入音频桥开发。[固定版本动作源码](https://github.com/LuwuDynamics/rig_omni/blob/c2b42cd73ef65f5cd2a158d6949f0273869454dc/main/boards/arm/arm_board.cc#L620)
- [ ] **语音桥｜开发者负责。** 实测原固件播报期间麦克风是否持续上送，核有无可用播放参考及回声抑制。实现终端到主机的麦克风上行、主机到终端的播放下行、队列上限和取消确认。主机保留豆包、方舟与记忆，终端只缓存当前有效音频。覆盖播放中插话、网络抖动与重连后的旧包丢弃。[板型二次开发](https://wiki.xgorobot.com/kb/pet-arm/f7ae72301c174cbf915284b728655236)
- [ ] **独立日用｜开发者部署，你插线复验。** 先用 Mac 做桥接短测，再将服务迁到成品 Linux 主机。验证实体聊天键、静默启动、两设备状态同步、短按保存关机及再次开机，关闭摄像服务和不需要的关节行为。采集插电使用时的电量、意外重启和掉线记录。

**决定下一步。** 首先取得实际距离的字幕试读和连续供电条件。若任一项已无法满足，或要拆机改电源，暂停。若本体双讲失败，单列外接成品会议麦的成本和声源变化后再评价。工程总投入初估 **80–160 小时，其中你现场约 12–24 小时**。拆分为固件启动与恢复 12–24、语音桥与调试 32–68、显示和关节 16–32、主机与电源联调 20–36 小时。

<a id="a1"></a>

### A1 M5StackChan K151 单机｜把现有业务移植到 ESP32-S3

**现场要做的事**是给一台 K151 接电、装卡、刷固件并做多轮中断和恢复测试。这条路线的主要代价在软件。Node 和浏览器里的现有业务无法原样运行在 MCU 上。[原路线与独立物料](hardware-options-comparison-and-shopping-list-2026-11-05.html#section-5)

- [ ] **板型与存储｜你接设备，开发者做基线。** 核 K151 标准整机、屏幕批次、USB 数据线和墙插，配兼容 microSD，记录稳定刷写与恢复步骤。测两轴、屏、麦克风、扬声器与 SD 卡同时工作时的剩余内存和供电稳定性。[K151 规格](https://docs.m5stack.com/zh_CN/StackChan/)
- [ ] **单机声音｜开发者负责，你现场插话。** 在目标固件先建麦克风持续采集、播放参考、扬声器输出和调试日志。连接豆包语音服务，验证流式收发、内存上限、清空旧声与断线重连。CoreS3 声卡代码声明双工，指定版本的设备侧 AEC 默认关闭，须在 K151 上证明能控回声。[编解码驱动](https://github.com/78/xiaozhi-esp32/blob/v2.5.2/main/boards/m5stack/core-s3/cores3_audio_codec.cc#L7-L14) · [固件配置](https://github.com/m5stack/StackChan/blob/28b9f0c8bd6acd81cb3c70f1a93c3e373b39d400/firmware/main/Kconfig.projbuild#L735-L760)
- [ ] **业务移植｜开发者负责。** 将已有会话、超时、模式、记忆冲突与恢复规则按测试样例移植到固件。定义 SD 的文字历史、记忆、日志和待提炼任务格式，实测卡满、关机前中断和重启恢复。把共用业务新增功能所需的调用接口接到 MCU，完成当前 Mac 回归样例的对应回放。
- [ ] **交互与维护｜开发者编写，你体验。** 适配本批次屏幕、字库和状态眼睛，映射原装关节及输入。通过配置文件提供音量、服务凭证和日志维护。你分别测试独立聊天输入与电源短按循环，核原装长按关机能否改写、有线扩展能否从外部实现。

**决定下一步。** 先用最小固件同时跑语音、屏幕与持续写卡，并验证可用 RAM 和独立按钮。若多轮中资源耗尽、原机必须动电路或没有所需扩展路径，停止移植，优先转 A2 复用 Linux 业务。工程总投入初估 **160–320 小时，其中你现场约 18–36 小时**。拆分为板级与电源 24–48、实时语音 40–80、业务与持久化移植 64–128、交互和恢复联调 32–64 小时。

<a id="a2"></a>

### A2 M5StackChan K151＋专用主机｜保留机身收音和发声

**现场要做的事**是给两台成品通电、刷 K151 并在真实距离试聊。Linux 保留现有 Jarvis 服务。要新开发的核心是能实时打断的双向语音桥。此前所核社区 USB 实现收放互斥，另有开源网络固件能驱动同款实体与自托管服务。[已核 USB 桥](hardware-route-review-2026-11-01.md) · [社区替代固件](https://github.com/7H3-CH053N/StackChan-CustomFW)

- [ ] **到货基线｜你接线和刷写。** 先用 Mac＋K151 验证机身能力，存好原厂固件、屏幕批次和恢复流程。用两轴及绘字示例出一段点头、转头、眼睛和字幕演示。验证方向成立后再配含电源、存储和散热的专用 Linux 整机。[官方舵机与绘字示例](https://docs.m5stack.com/en/arduino/stackchan/servo)
- [ ] **双向语音｜开发者负责。** 选定可同时上行和下行的固件与传输方式，记录采样率、帧长、时间戳、缓冲和回声参考。将主机的豆包音频送至机身播放，接回麦克风，确认能在机器人说话时收到人声。收到插话后立即终止旧轮，清空机身播放并回报停播时刻。
- [ ] **表达及重连｜开发者负责，你检验。** 桥协议传递会话标识、表情、有限幅度的两轴动作、字幕和按键事件。你在收音、播音和动作中分别断开一次本地链路，核重连后旧语音和旧动作都不再恢复。主机保留既有记忆和模式文件。
- [ ] **双设备日用｜开发者接入，你实际按键。** 在目标 Linux 上部署自启动及日志，确认拔掉 Mac 后可用。验证机身与主机冷启动、按键启用、聊天、短按关机与再次开机，记录是否需要人工多按一次或拆机增线。
