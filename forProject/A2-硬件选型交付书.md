## 软硬件分工

**K151** 经家用 2.4 GHz Wi-Fi 与主机建立配对连接，底座 USB-C 用于供电、刷写和维护。终端读聊天键和电源键，采集麦克风及扬声器参考信号，播放语音，本地绘制双眼与一两行字幕，执行有限的点头和左右转动指令。机身已有电池，日常验证按长时间插电场景进行；摄像头默认停用。先在小角度检查外接按钮线的活动余量，再标定两轴限位。[接口与固件依据](docs/k151-hardware-plan-2026-11-08.md)

**Mac → Linux 主机** 承载同一套 Jarvis 会话逻辑，连接豆包实时语音及方舟，维护记忆、Skill、配置和日志。云服务凭证保存在主机，本地长期保存文字历史，默认不保存原始录音。日用 Linux 可从 Ubuntu 24.04 LTS 起验证。未来 NVIDIA Jetson 按独立供电的有线局域网节点预留，在路由器或交换机上核实可用端口。[PRD](../prd/prd-v1.1.md) · [现有语音入口](../prototypes/voice/server.mjs)

**音频与设备协议** 从机身取得同步的 24 kHz 麦克风和播放参考 PCM，主机消回声后转 16 kHz 单声道、每 20 ms 640 字节送入既有语音服务，回答以 24 kHz 返回。现有 `npm run voice` 服务只接受本机网页，保留其回环和来源校验，另做配对设备入口。音频帧带序号，会话和回答有编号；收到取消后机身清空旧音频与动作并回报实际播放状态，重连丢弃旧帧。Mac 的既有回环使用合成输入、模拟识别及虚拟播放，终端固件和 Wi-Fi 仍待联调。[音频参数](../prototypes/voice/config.mjs) · [取消逻辑](../prototypes/voice/guard.mjs) · [播放回执](../prototypes/voice/playback.mjs)

**两个按键各有职责**。首次通电进入黑屏未启用，按一次机身侧键启用眼睛，按 U027 开始聊天。运行中按侧键立即停交互，主机保存文字和待提炼队列，确认受理后执行安全关机，机身关闭舵机及电源。关机后按同一侧键开机，K151 经家用局域网唤醒有线 NUC，保持黑屏；再按一次启用。台架分别观测机身启动原因和 NUC 关机日志、启动编号。正式电源测试使用底座墙插，拔掉第二路调试 USB 供电。[电源设计与故障处理](docs/k151-hardware-plan-2026-11-08.md)
